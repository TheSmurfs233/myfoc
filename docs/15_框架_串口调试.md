## 3. 关键参数

| 项 | 值 | 位置 |
|---|---|---|
| 串口 | **USART1，PB6=TX / PB7=RX** | `usart.c` |
| 波特率 | **1 000 000** 8N1，无流控 | `usart.c` |
| 实际波特率 | ≈999.7 kbaud（BRR 取整，误差 0.03%） | 计算 |
| RX | DMA1_CH1，**运行时改成 CIRCULAR** | `bsp_uart.c` |
| TX | DMA1_CH2，NORMAL（分块链式） | `bsp_uart.c` |
| RX DMA 缓冲 | 128 B | `DBG_RX_BUF_SIZE` |
| RX 解析缓冲 | 1024 B | `DBG_RX_RING_SIZE` |
| TX 发送缓冲 | 4096 B | `DBG_TX_RING_SIZE` |
| TX 单次 DMA 块 | 64 B | `DBG_TX_DMA_CHUNK` |
| 中断优先级 | USART1=3，DMA1_CH1/2=2（ADC=0 最高） | `.ioc` |

### 3.1 为什么 RX DMA 要改成 CIRCULAR

CubeMX 生成的是 `DMA_NORMAL`。NORMAL 模式下：
- 收满 128 字节后 DMA 停止，必须软件重启，重启间隙会丢字节；
- IDLE 之后虽然还能继续收，但位置会"顶到头"。

`bsp_uart_init()` 里在运行时把模式改成 CIRCULAR（**不改 .ioc**）：

```c
hdma_usart1_rx.Init.Mode = DMA_CIRCULAR;
(void)HAL_DMA_Init(&hdma_usart1_rx);
(void)HAL_UARTEx_ReceiveToIdle_DMA(&huart1, s_rx_dma_buf, DBG_RX_BUF_SIZE);
```

> CubeMX 重新生成代码后，`HAL_UART_MspInit` 会把它写回 NORMAL，
> 但 `app_init()` 里再调一次 `bsp_uart_init()` 就又覆盖回来，**无需人工干预**。

### 3.2 位置跟踪（回绕处理）—— 必须按事件类型判断

IDLE / 半满 / 全满 事件都会进 `HAL_UARTEx_RxEventCallback(huart, Size)`，
`Size` = DMA 当前写入位置（0~128）。**光靠比较 Size 和 last 是不够的**：

> 环形缓冲区写满一圈时，HAL 上报的是 `Size = RxXferSize`（= 128），
> 且 DMA 位置归零重新开始。如果连续两圈都是"满"，两次上报的 `Size` 都是 128，
> `Size == last` 就会把**整圈 128 字节静默丢掉**。

正确做法：用 `huart->RxEventType` 区分事件来源。

```c
if ((huart->RxEventType == HAL_UART_RXEVENT_TC) || (Size >= DBG_RX_BUF_SIZE)) {
    /* 整圈刚满：搬 last..END，位置归零 */
    push(&rx_buf[last], DBG_RX_BUF_SIZE - last);
    s_rx_last_pos = 0;
    return;
}
/* IDLE / HT：Size 就是当前位置 */
if (Size == last) return;
if (Size > last) push(last..Size);
else            { push(last..END); push(0..Size); }   /* 位置倒退 = 回绕 */
s_rx_last_pos = Size;
```

这个 bug 是主机仿真抓出来的（`test/README.md` 第 5 节），
只在**持续不间断接收**时出现，手敲命令永远测不到。

## 4. 时序/数据流

```
PC ──1Mbaud──► PB7 ──► DMA1_CH1(CIRC) ──► rx_dma_buf[128]
                                              │
                              IDLE / 半满 / 全满 中断（prio 2）
                                              ▼
                              HAL_UARTEx_RxEventCallback
                                   └─ ring_push → rx_ring[1024]
                                              │
        主循环 app_loop()                      ▼
        └─ app_cmd_poll() ──► 按 \r/\n 切行 ──► cmd_exec() ──► 业务

        app_loop()
        └─ task_wave() ──► vofa_send() ──► tx_ring[4096]
                                              │
        app_loop()                            ▼
        └─ bsp_uart_tx_pump() ──► tx_dma_buf[64] ──► DMA1_CH2 ──► PB6 ──► PC
                    ▲
                    └── TxCpltCallback 只清 tx_busy，不递归启动
```

### 4.1 非阻塞的三条硬保证

1. **`bsp_uart_tx_write()` 只做 `ring_push`**，写不进去就返回实际写入字节数，**绝不等待**。
2. **`bsp_uart_tx_pump()` 每次最多搬 64 字节**就返回，只启动 DMA，不轮询 TC 标志。
3. **`HAL_UART_TxCpltCallback` 里只清一个标志**，不在中断里再启动 DMA（避免 DMA 状态竞争）。

> 结果：串口再忙也只会"丢日志/丢波形帧"，**永远不会拖慢主循环**，更不会影响 FOC 电流环
> （电流环在 ADC 中断里，优先级 0，串口 DMA 是 2，USART 是 3）。

### 4.2 为什么 `pump()` 放在主循环而不是中断里

主循环频率实测在 **50~100kHz** 量级（`stat` 命令可看），
64 字节 @1Mbaud 需要 640µs 才发完，主循环有充足时间在下一次 DMA 完成前重新启动。
中断里重启 DMA 虽然少几微秒间隙，但会引入 `HAL_DMA_Start_IT` 的状态竞争风险，不值得。

## 5. 上行：VOFA+ FireWater（CSV）协议

> **决策链**：JustFloat(二进制) → FireWater(`name:value`) → **FireWater(纯 CSV)**。
> 最终采用纯 CSV，依据是 VOFA+ 官方帮助页给出的格式定义（见 5.1）。

### 5.1 帧格式（VOFA+ 官方定义）

```
"ch0,ch1,ch2,...,chN\n"              纯 CSV（本项目用这个）
"<any>:ch0,ch1,...,chN\n"            行首可带一个任意标签
```

官方例子：

```c
printf("samples: 1.1, 3.2, -0.6, -0.9\n");
printf("1.1, 3.2, -0.6, -0.9\n");
```

本项目实际输出（6 通道、3 位小数）：

```
169.347,1.000,0.000,2.000,-773.000,452.542\n
```

#### ⚠ 铁律 1：冒号**只能出现一次，且在行首**

`t:1.0,st:2.0,md:0.0` 是**错的** —— 第二个冒号会让解析失败，
VOFA+ 退回把这行当**文本**显示，于是波形帧全跑到数据区刷屏（2026-10-25 踩过这个坑）。

#### ⚠ 铁律 2：必须 `\n` 结尾

> VOFA+ 帮助页原文："FireWater 遇到换行才会打印数据，很多新用户在这里产生疑惑。"

一行没发完之前，VOFA+ 不会提交任何数据点。

### 5.2 通道顺序（6 通道，约 44 字节/帧）

通道名**不在数据里**，VOFA+ 显示为 `ch0..ch5`，可在界面里手动改标签。

| 位置 | 含义 | 备注 |
|---|---|---|
| ch0 | 运行时间 s | `HAL_GetTick()/1000` |
| ch1 | 状态机 | 0=INIT 1=IDLE 2=RUN 3=FAULT |
| ch2 | 控制模式 | 0=IDLE 1=OPENLOOP 2=FOC |
| ch3 | 按键次数 | 验证按键链路 |
| ch4 | 测试正弦 ±1000 | 内部 1Hz，**64 点表 + 线性插值**（不插值会有明显台阶） |
| ch5 | 主循环频率 kHz | 反映 CPU 余量 |

> S3 之后 ch1~ch5 换成真实量（ia/ib/ic、vbus、id/iq），ch0 保持时间轴。

**关于"锯齿"**（2026-10-25 用户反馈）：

| 现象 | 原因 | 处理 |
|---|---|---|
| 正弦呈阶梯 | 64 点表在 500Hz 下每个值重复 ~8 帧 | ✅ 已改为**表间线性插值**，曲线连续 |
| `ch5`(khz) 呈台阶 | 主循环频率每 1s 才更新一次 | 正常。不想看就在 VOFA+ 里隐藏该通道 |
| 整条曲线横向被压缩/拉伸 | VOFA+ 的 `Δt` 设错（默认 1ms，实际 2ms@500Hz） | 把 `Δt` 改成 **2 ms**，或用 Auto |
| 曲线上有缺口/跳点 | 丢帧（`stat` 里 `drop` 在涨） | `rate` 降一档 |

### 5.3 日志行怎么保证不被当成数据

两个手段（`mid_log.c`）：

1. **每条日志前加 `[log] ` 标记**（6 字节）
2. **日志里禁止出现冒号**，统一用 `=`（否则会命中 `<any>:数字列表` 的形态）

于是日志长这样：

```
[log] uptime = 12345 ms
[log] state    = IDLE
[log] ERR usage=mode <0|1|2>
```

它不是纯数字 CSV，也没有行首冒号 → **VOFA+ 只能把它当文本显示** ✅

自检（输出必须为空）：
```bash
grep -rn 'log_printf("[^"]*:' User/
```

### 5.4 为什么数据区不再被波形刷屏

| 行类型 | 形态 | VOFA+ 行为 |
|---|---|---|
| 波形帧 | `169.3,1.0,0.0` | 解析成数据 → **只进图，不进文本区** |
| 日志行 | `[log] uptime = 12345` | 解析失败 → 显示为文本 |

所以接收区里**只剩 `[log]` 开头的日志**，波形只出现在波形面板 —— 这才是"既要波形又要文本"的正确姿势。

### 5.5 带宽与速率

```
每帧 ≈ 44 字节（6 通道，3 位小数，如 "169.347,1.000,0.000,2.000,-773.000,452.542\n"）

 100 Hz →  4.4 kB/s ≈  44 kbps → 1Mbaud 的  4%（默认）
 300 Hz → 13.2 kB/s ≈ 132 kbps → 1Mbaud 的 13%
 500 Hz → 22.0 kB/s ≈ 220 kbps → 1Mbaud 的 22%（上限）
1000 Hz → 44.0 kB/s ≈ 440 kbps → 1Mbaud 的 44%（不做，余量不足）
```

- 上限 **500Hz**（`DBG_WAVE_RATE_MAX`），`rate` 超过自动钳位
- **默认 = 上限 = 500Hz**（`DBG_WAVE_RATE_HZ` 直接引用 `DBG_WAVE_RATE_MAX`）——
  上电 `wave on` 就是最高速率，想轻一点用 `rate 100` 降下来
- 理论天花板 **1000Hz**（`HAL_GetTick` 1ms 分辨率），但那时要 44% 带宽、每毫秒必中，不做
- 为什么不到 1000Hz：
  1. 44% 总线占用，单环缓冲没有余量吸收抖动，容易丢帧
  2. `HAL_GetTick` 只有 1ms 分辨率，1000Hz 要求 task_wave 每毫秒必中，一次打嗝就掉帧
  3. 500Hz 对 20kHz 电流环已有 40 点/周期，S6 观察阶跃够用

### 5.6 VOFA+ 设置步骤

1. VOFA+ → 数据格式选 **FireWater**
2. 串口选 COM 口，波特率 **1000000**，8N1
3. 点「连接」
4. 发送 `wave on`
5. 波形区出现 6 条曲线（`ch0..ch5`），`ch4` 是 1Hz 正弦、`ch0` 是上升斜坡
6. 同时在接收区发 `help`/`ver`/`stat`，只会看到 `[log] ...` 开头的文本

## 6. 下行：ASCII 文本命令

### 6.1 协议

PC → MCU：一行 ASCII，以 `\r` 或 `\n` 结尾，命令与参数空格分隔。
MCU → PC：人类可读文本（以 CRLF 结尾）。

> **文本行和 JustFloat 二进制帧可以混在同一个串口里互不干扰**：
> JustFloat 靠帧尾 `00 00 80 7F` 定界，文本行靠 `\r\n` 定界，两者不会误判。
> （VOFA+ 的波形区只解析 JustFloat，文本会显示在"数据"面板或忽略。）

### 6.2 命令表

| 命令 | 作用 | 示例回复 |
|---|---|---|
| `help` | 打印命令列表 | `---- commands ----` |
| `ver` | 版本、板级、PWM/电流/母线参数 | `board : Board_v2/...` |
| `stat` | 运行状态快照 | 状态、模式、LED、按键、循环频率、波形/串口统计 |
| `start` | 启动（需先选模式） | `OK start, mode=OPENLOOP` / `ERR mode=IDLE...` |
| `stop` | 停止并封波 | `OK stop, PWM off` |
| `mode <0\|1\|2>` | 0=IDLE 1=OPENLOOP 2=FOC | `OK mode=FOC` / `ERR stop the motor first` |
| `led <on\|off\|toggle>` | 控制 PF1 LED | `OK led ON` |
| `wave <on\|off>` | VOFA+ 波形上报开关 | `OK wave ON @ 1000 Hz...` |
| `rate <hz>` | 波形速率 1~500，默认 500 | `OK rate = 500 Hz` |
| `clr` | 清零计数器 | `OK counters cleared` |
| `echo <text>` | 回显测试 | 原样返回 |

出错时统一 `ERR <原因>`，未知命令提示 `try 'help'`。

### 6.3 解析位置与纪律

- **字节搬运在中断**（DMA 回调 → ringbuf），**解析全在主循环**。
- 单行最长 63 字节，超出直接丢弃并报 `ERR line too long`。
- 支持退格 `0x08/0x7F`，忽略其它控制字符。

## 7. 轻量格式化（不依赖 stdio）

`log_printf` 自己实现格式化，**不用 `printf`/`vsnprintf`**，理由：
- Keil 下 `printf` + 浮点会拉入大量库代码，且需要 MicroLIB；
- `printf` 走 semihosting/重定向容易半阻塞，破坏非阻塞承诺；
- 自己实现可以精确控制栈和代码体积（用静态缓冲，不占栈）。

支持的格式：`%d %i %u %x %X %s %c %f %%`，可带 `0` 填充和宽度（`%08x %4d %-8s`）。
- `%f` 固定输出 **2 位小数**（`%.3f` 这类精度修饰会被吞掉，仍按 2 位输出）
- 单条日志上限 **128 字节**，超出截断
- **只能在主循环调用**，中断里禁止（用的是静态缓冲）

## 8. 为什么不用"二进制帧 + CRC16"

早期方案（`0xAA 0x55 | LEN | CMD | PAYLOAD | CRC16`）在 S1 阶段被弃用，原因：

| 维度 | 二进制帧 | ASCII 文本（选定） |
|---|---|---|
| 调试效率 | 要用脚本或自研上位机发 | 串口助手/VOFA+ 发送区直接敲 |
| 出错可见性 | CRC 错 → 静默丢弃，难定位 | 打错字立刻 `ERR unknown cmd` |
| 实现复杂度 | 状态机 + CRC 表 + 粘包处理 | 切行 + `strcmp` |
| 带宽 | 略省 | 命令频率极低（人工敲），无所谓 |

**唯一的代价**：如果将来要做"高速参数批量下发"，文本会偏低效。
届时可以再补一套二进制帧**并存**（`0xAA 0x55` 帧头与 ASCII 首字节天然不冲突）。

### 10.1 真机验收脚本

`test/accept/s1_accept.py` 把上面这张表自动化，覆盖 11 组共 53 项断言。
设计要点：**每个读操作都带硬超时**（`quiet` + `max_seconds`），所以即使板子正在
`wave on` 持续吐 500Hz 波形，脚本也绝不会挂死。

脚本开头会先发 `wave off` 停流，结束前再发一次。

### 10.2 固件版本识别：`FW_BUILD_ID`

`board_cfg.h` 里的 `FW_BUILD_ID`（当前 **13**）是**唯一权威**的版本标识，`ver` 会打印成
`build = Oct 25 2026 02:46:xx #13`，验收脚本会拿它和磁盘上的 `board_cfg.h` 比对。

> **⚠ 不要用 `__DATE__/__TIME__` 判断固件新旧。**
> Keil ARMCC 是**增量编译**：只改了 `mid_log.c` 的那次 build 就只重编 `mid_log.c`，
> 而 `__TIME__` 写在 `app_cmd.c` / `app_main.c` 里，它们的 `.o` 不重编 ——
> 结果就是**镜像是新的、内嵌时间戳还是旧的**，据此判断会误判。
>
> 顺带解决：改 `board_cfg.h` 会触发所有包含它的文件重编，`__TIME__` 也跟着刷新。
> 所以 **每次改固件记得把 `FW_BUILD_ID` +1**。

### 10.3 ⚠ 两个工程都叫 `myfoc`，别下错

```
D:\Embedded\STM32\wb_foc\MDK-ARM\myfoc\myfoc.hex     <- 本工程（约 68 KB）  ✅
```

- 【已知限制】`HAL_GetTick` 只有 1ms 分辨率，波形速率上限 1000Hz。要更高需改用 DWT 计数器或定时器。
- 【已知限制】TX 缓冲满时**静默丢弃**（`vofa_send` 返回 0 并计数，`log_printf` 不计数）。
  `stat` 里的 `wave drop` 可观察。
- 【已知限制】`log_printf` 不可重入、不可在中断调用。
- 【TBD】是否需要二进制帧通道（高速参数下发）——等 S7 调参时再看。
- 【TBD】板载 CH340N（USART2）是否启用——如果要"一根 USB 线"，需在 CubeMX 加 USART2 + DMA。
- 【已知限制】CN3 是 1.0mm 间距排针，需要转接线。
