# 主框架

> 本文是整套工程的"总图"。子框架文档只写细节，**分层、时序、优先级、目录约定以本文为准**。

---

## 1. 职责边界

主框架不实现任何控制算法，只定义：
- 代码分层与依赖方向（谁能调谁）
- 20kHz 电流环的**中断时序与时间预算**
- 中断优先级分配
- 全局状态机与初始化顺序
- 目录与命名约定

## 2. 分层结构

```
┌──────────────────────────────────────────────────────────┐
│ App  应用层   app_main / app_state(状态机) / app_cmd(命令解析) │
│              只做"什么时候干什么"，不做数学                    │
├──────────────────────────────────────────────────────────┤
│ Alg  算法层   foc_core(Park/Clarke/PI/反Park) / svpwm       │
│              纯数学，无 HAL 依赖，可单元测试                   │
├──────────────────────────────────────────────────────────┤
│ Mid  中间件   mid_current(换算+校准) / mid_angle(角度处理)    │
│              mid_ringbuf / mid_log(带缓冲打印)               │
├──────────────────────────────────────────────────────────┤
│ Bsp  驱动层   bsp_pwm / bsp_adc / bsp_spi / bsp_uart / gpio │
│              唯一允许直接调 HAL 的层                          │
├──────────────────────────────────────────────────────────┤
│ Core CubeMX  外设初始化（MX_xxx_Init），只在 USER CODE 段扩展  │
└──────────────────────────────────────────────────────────┘
```

**依赖方向严格单向向下**：App → Alg → Mid → Bsp → HAL。
反向通信只能通过：(1) 全局只读状态结构体；(2) 回调函数指针。

**为什么算法层不能碰 HAL**：S4 之前在 PC 上就能验证 Clarke/Park/SVPWM 的数值，
以及后期换芯片（G431→G474）时算法层零改动。

## 3. 20kHz 时序（核心）

```
              |<------------------- 50us (20kHz) ------------------->|
              |                                                       |
TIM1 CNT  ────┐ 峰顶(ARR)                                              ┌──
  中心对齐     │╲                                                     ╱│
             0 ┘ ╲___________________________________________________╱ └ 0
                    ↑CC4 上升沿                    ↑CC4 上升沿
                    │                               │
ADC2 注入组        ▓▓▓ 2.61us                      ▓▓▓ 2.61us
(3 通道顺序)        │                               │
JEOC 中断           ▼ FOC 计算 ≤ 8us               ▼ FOC 计算
                    │  ├ 读 JDR1/2/3                │
                    │  ├ 读角度(SPI 上次值或本次)    │
                    │  ├ Clarke→Park→PI→反Park      │
                    │  ├ SVPWM → 写 CCR1/2/3         │
                    │  └ 故障检测                    │
                    └───────── 空闲 40us ────────────┘
```

**要点**
1. 采样点 = 三角波**峰顶**（PWM 周期中心），此时距两侧开关沿最远。采样电阻**串在相线里**
   （inline），相电流连续流过，所以峰顶也能采到真实电流（不是低侧三电阻方案）。
2. 电流环触发链：`TIM1_CH4(CCR=ARR) → ADC2 注入组 → JEOC 中断 → FOC`。
   **不使用 TIM1 更新中断**（中心对齐 RCR=0 时 UEV 每半周期发生两次，会双倍负载）。
3. 从触发到算出新 CCR 的总延迟 = 2.61µs(ADC) + 计算时间。相对 50µs 周期约 5~20%，
   Park 变换的角度应使用**当前采样时刻**的角度，而不是下一周期角度（后者等价于提前一拍）。

**时间预算（@170MHz，50µs = 8500 周期）**

| 环节 | 预算 | 说明 |
|---|---|---|
| ADC 注入转换 | 2.61 µs | 硬件，不可压缩（除非改双 ADC） |
| 读 3 个 JDR + 换算 | 0.2 µs | 直接读寄存器，别用 HAL 函数 |
| MT6701 SPI 读（若在中断内） | 1.5~3 µs | 16bit@10MHz ≈ 1.6µs + 开销；**S5 再定是否挪到 DMA/上周期值** |
| Clarke + Park + PI + 反Park | 1.5 µs | 含算 sin/cos（LUT） |
| SVPWM + 写 CCR | 0.5 µs | |
| 故障检测 | 0.2 µs | |
| **ISR 合计目标** | **≤ 8 µs（16%）** | S6 用 GPIO 翻转 + 示波器实测 |

### 3.1 实测时序（#54，2026-10-25）

| 环节 | 实测 | 说明 |
|---|---|---|
| ADC 触发 → 中断入口 | `isr cnt 3689..3711` ≈ **28.3 µs**（周期内位置） | 抖动 ±22 counts = 0.26 µs |
| `pick`（中断 → 主循环取帧） | **2.8 µs** | 受主循环周期影响 |
| `comp`（取帧 → 占空比算完） | **7.5 µs** | 电流换算 + V/f + SVPWM |
| `wr`（算完 → 写 CCR） | **2.7 µs** | 3 路 CCR + 浮点转整数 |
| `enc`（编码器一帧） | **6.2 µs** | 位于控制链**之后**，不占实时路径 |
| ISR 本体 | **1.48 µs** | 含 prof 打点，`prof off` 后约 0.6 µs |

时间轴（RUN，20kHz）：

```
0 ─── 28.3 ── 31.1 ── 38.6 ── 41.3 ── 47.5 ──────── 50 µs
谷底    中断    取帧   comp    写CCR   enc 完      谷底 UEV
                 └──── 控制链 13.0 µs ────┘  └6.2┘
```

编码器在 CCR 之后，**即使越界也只会推迟下一帧取帧，不会破坏本帧占空比**。

### 3.2 S6（电流环）的裕度核算

FOC 要求 **Park 变换前就拿到角度**，所以 S6 里编码器必须挪到计算之前：

| 方案 | 时间轴 | 合计 | 余量 |
|---|---|---|---|
| S6 沿用阻塞读（编码器在计算前） | 28.3 + 2.8 + **6.2** + 10（含 PI） + 2.7 | **50.0** | **0** ❌ |
| S6 + SPI DMA（编码器后台传） | 28.3 + 2.8 + 10 + 2.7 | 43.8 | **6.2** ✅ |
| S6 + 控制环进 ISR | 28.3 + 10 + 2.7 | 41.0 | **9.0** ✅ |
| S6 + DMA + 控制环进 ISR | 28.3 + 10 + 2.7 | 41.0 | **9.0** ✅ 最稳 |

**结论**：S6 **必须**上 SPI DMA（或把控制环搬进 ISR），否则阻塞读会吃掉全部余量。
这条已写进 `docs/14` §7.4 的优化路线。

## 4. 中断优先级

`NVIC_PRIORITYGROUP_4`（4 位抢占 + 0 位子优先级），**数值越小优先级越高**。

| 中断 | 抢占优先级 | 理由 |
|---|---|---|
| `ADC1_2_IRQn`（JEOC） | **0** | 20kHz 硬实时，绝对最高 |
| `DMA1_Channel1/2_IRQn`（串口） | 2 | 不能挡住 FOC |
| `USART1_IRQn`（IDLE） | 3 | 只做"帧到达"标记 |
| `SysTick_IRQn` | 15 | HAL 时基 |

✅ **2026-10-25 已确认**：`.ioc` 与生成代码中 ADC1_2=0、DMA1_CH1/2=2、USART1=3、SysTick=15，
与上表一致，无需再改。

**ISR 纪律**
- FOC ISR 里禁止：`printf`、浮点除法以外的循环等待、任何 `HAL_Delay`、动态内存。
- FOC ISR 里允许：读写外设寄存器、算浮点（G431 有单精度 FPU）、置标志位。

## 5. 状态机

```
       上电
        │
        ▼
   ┌─────────┐  自检通过   ┌────────┐  启动命令  ┌────────┐
   │  INIT   │───────────▶│  IDLE  │──────────▶│ ALIGN  │
   └────┬────┘            └───┬────┘           └───┬────┘
        │ 自检失败             ▲                   │ 预定位完成(固定 Ud, θ=0)
        ▼                     │                   ▼
   ┌─────────┐  清故障         │              ┌────────┐
   │  FAULT  │────────────────┘              │ OPENLP │ V/F 开环（S4）
   └─────────┘                               └───┬────┘
        ▲                                        │ 切入闭环
        │ 任意状态检测到故障                      ▼
        └──────────────────────────────────┌────────┐
                                           │  RUN   │ 电流环 + 速度环
                                           └────────┘
```

- **ALIGN**：d 轴电流固定值、θ 强制 0，把转子拖到已知位置，持续 300~500ms，用于零位标定/开环起转。
- **OPENLP**：S4 阶段用于验证相序与 SVPWM，不依赖传感器。
- **FAULT**：立即 `MOE=0` 封波，记录故障码，只允许命令清除。

## 6. 初始化顺序（main.c 的 USER CODE 段）

```
HAL_Init → SystemClock_Config → MX_GPIO/DMA/USART/TIM1/SPI/ADC2
  → app_init()                     // 实际实现在 User/App/app_main.c
        ├─ bsp_gpio_init()         // PA0 上拉、LED 熄灭
        ├─ bsp_uart_init()         // RX DMA 切 CIRCULAR、启动 ReceiveToIdle
        ├─ app_cmd_init()
        └─ 打印 banner，状态进 IDLE
  → while(1) { app_loop(); }
        ├─ bsp_key_poll() + key_action()   // 按键消抖与动作
        ├─ app_cmd_poll()                  // 命令解析（主循环）
        ├─ bsp_uart_tx_pump()              // DMA 发送推进
        ├─ task_1ms()                      // uptime / 循环频率
        └─ task_wave()                     // VOFA+ 波形

【S2 起要插入的步骤】
  → bsp_pwm_init()           // 起波前先 ADC 校准，再 MOE=0 待命
  → mid_current_init()       // 零漂校准必须在 PWM 完全关断时做
  → 使能 ADC 注入组 + TIM1 CC4 触发
```

**ADC 校准必须在 PWM 输出之前做**，否则 INA240 输出会被开关噪声污染，
零漂校准值带有偏移，表现为低速时电流直流偏置。

## 7. 目录与命名约定

```
User/
  Cfg/   board_cfg.h    所有板级常量（时钟/PWM/死区/采样电阻/分压/LED与KEY极性/缓冲大小）
         foc_cfg.h      【S6 建】控制参数（极对数、R、L、PI、限幅、保护阈值）
  Bsp/   bsp_gpio.c      LED / KEY
         bsp_uart.c      调试串口（DMA + ringbuf）
         bsp_pwm.c       TIM1 发波、CCR 写入、启停（S2 已实现）
         bsp_adc.c       【S3】注入组读取、JEOC 回调
         bsp_prof.c      【S3】DWT 周期计数（阶段耗时）
         bsp_flash.c     【S3】页擦/双字编程（校准记录持久化）
         bsp_mt6701.c    【S5】SPI 读角度
  Mid/   mid_ringbuf.c   环形缓冲
         mid_log.c       轻量格式化
         mid_vofa.c      VOFA+ FireWater（纯 CSV）
         mid_current.c   【S3】电流换算、零漂、Flash 记录
         mid_angle.c     【S5】角度处理
  Alg/   alg_svpwm.c     【S4】min-max 注入 SVPWM（已实现）
         alg_vf.c        【S4】角度累加 + V/f 曲线（已实现）
         alg_clarke.c    【S6】
         alg_park.c      【S6】
         alg_pi.c        【S6】
         alg_foc.c       【S6】
  App/   app_main.c      状态机 + 主循环调度 + task_vf
         app_cmd.c       文本命令解析
```

**已完成（S1）**：`board_cfg.h`、`bsp_gpio`、`bsp_uart`、`mid_ringbuf`、`mid_log`、`mid_vofa`、
`app_main`、`app_cmd`。
**已完成（S2）**：`bsp_pwm`（`PWM_CCR_MIN/MAX`、`PWM_START_DUTY` 在 `board_cfg.h`）。
**已完成（S3）**：`bsp_adc`、`bsp_prof`、`bsp_flash`、`mid_current`（含 Flash 校准记录）。
**已完成（S4）**：`alg_svpwm`、`alg_vf`、`task_vf`（`VF_*` 在 `board_cfg.h`）。
**约定**：文件名前缀 = 所属层（`bsp_` / `mid_` / `alg_` / `app_`），函数名与文件名一致。

- 宏全大写下划线；配置类宏统一放 `board_cfg.h`（板级）/ `foc_cfg.h`（控制），
  **代码里不允许出现魔法数字**。
- **源码必须纯 ASCII**：注释和字符串都用英文。ARMCC V5 按 GBK 解析，
  UTF-8 中文放进字符串字面量会报 `#8: missing closing quote`。中文说明写进 `docs/`。
- 每个模块 `.h` 里用 `extern "C"` 包裹（便于将来上 PC 仿真）。
- CubeMX 生成的 `xxx.c` 只在 `USER CODE BEGIN/END` 之间改动；**重新生成前必须确认这些段存在**。
