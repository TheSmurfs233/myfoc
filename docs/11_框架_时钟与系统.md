# 子框架 · 时钟与系统

---

## 1. 职责边界

保证：主频 170MHz、各外设时钟源与分频、Flash 等待周期正确、启动流程可控。
不涉及外设功能配置（在各 BSP 文档里）。

---

## 2. 接口

| 项 | 位置 | 说明 |
|---|---|---|
| `SystemClock_Config()` | `Core/Src/main.c` | CubeMX 生成，不改 |
| `SystemCoreClock` | CMSIS | 应为 170000000，`bsp_sys_selftest()` 里校验 |
| `HAL_InitTick()` | HAL | SysTick 1ms，优先级 15 |

---

## 3. 关键参数（时钟树）

```
HSI 16MHz ──▶ /M=4 ──▶ 4MHz ──▶ ×N=85 ──▶ VCO 340MHz ──┬─ /R=2 ─▶ SYSCLK 170MHz
                                                        ├─ /P=2 ─▶ 170MHz (未用)
                                                        └─ /Q=2 ─▶ 170MHz (未用, 若用 USB 需调)
SYSCLK 170MHz ──▶ AHB /1 ─▶ HCLK 170MHz
                        ├─ APB1 /1 ─▶ 170MHz  (TIM 时钟 = 170MHz，无倍频)
                        └─ APB2 /1 ─▶ 170MHz
ADC12 时钟源 = SYSCLK，ADC 分频 = /4 ─▶ 42.5MHz（G4 上限 60MHz ✓）
USART1 时钟源 = PCLK2 = 170MHz
SPI1  时钟源 = PCLK2 = 170MHz，/16 ─▶ 10.625MHz
Flash latency = 4 WS，电压档 = SCALE1_BOOST（170MHz 必须开 BOOST）
```

**VCO 340MHz** 在 G4 允许范围（96~344MHz）内 ✓，但已接近上限，
若将来要改频率，注意别超过 344MHz。

---

## 4. 时序/数据流

```
复位 → SystemInit(CMSIS) →  
       main(): HAL_Init() → SystemClock_Config() → MX_*_Init() → 用户初始化
```

`SystemClock_Config()` 里两个必须成功的点：
1. `HAL_PWREx_ControlVoltageScaling(PWR_REGULATOR_VOLTAGE_SCALE1_BOOST)` —— 必须在配 PLL 之前
2. `HAL_RCC_ClockConfig(..., FLASH_LATENCY_4)` —— 170MHz 必须 4 WS，少了会 HardFault

---

## 5. 依赖

无（最底层）。被所有 BSP 依赖。

---

## 6. 验证方法

1. `bsp_sys_selftest()` 里断言 `SystemCoreClock == 170000000`，串口打印。
2. **间接验证**：PWM 输出用示波器测应为 20.000kHz —— 频率对说明时钟树对（这是最可靠的一步，
   因为 PWM 频率 = tim_clk / (2·ARR) 直接反映 tim_clk）。
3. 串口 1Mbaud 无乱码 → USART1 时钟源正确。

## 7. 已知限制与 TBD

### HSI 精度对本项目的影响（重要，结论：不影响控制）

- HSI16 常温精度 ±1%，全温区约 ±2~3%。
- 影响面：
  - PWM 频率 20kHz ±1% → 198~202Hz 偏差
  - ADC 采样率、ISR 周期同比偏移
- **不影响 FOC 控制**：PWM 周期、ADC 触发、ISR 计算全部来自同一时钟域，
  所有时间量是**同源比例**的，控制器看到的"每周期"始终一致。
- 真正受影响的只有跨时钟域的量：
  - 与上位机约定的采样率（如"每 1ms 上报一次"会有 1% 偏差）→ 用 SysTick 定时即可，无感
  - MT6701 的 SCK 频率（传感器有时序要求，±2% 通常没问题）
  - 若将来做无感观测器用反电动势常数换算转速 → 会有 ±1% 转速误差，闭环下被消除

### 为什么没有外部晶振

`.ioc` 中 PF0-OSC_IN / PF1-OSC_OUT 已被复用为 **TIM1_CH3N / LED**，
说明硬件上没给晶振（或晶振位被挪作他用）。当前 `RCC_OscInitStruct.OscillatorType = RCC_OSCILLATORTYPE_HSI`，
`.ioc` 里残留的 `HSE_VALUE=8000000` 是历史配置，未生效。

【TBD】如果板上有 8MHz 晶振且 PF0/PF1 实际没接到栅极驱动器，应改回 HSE（精度更好）。
**需要用户确认：PF0 是否真的驱动了 C 相下管？板上是否有晶振位？**

### 其他

- 【TBD】`ADC12Freq_Value=170000000` 在 .ioc 中是个误导字段（实际 ADC 时钟是 42.5MHz），
  不要以它为准，以 `adc.c` 的 `ADC_CLOCK_SYNC_PCLK_DIV4` 为准。
- 堆 0x200 / 栈 0x800：`printf` + 浮点格式化可能吃掉 500B+ 栈，
  若出现异常复位，优先怀疑栈溢出（S1 里加 `__get_MSP()` 水位检测）。
