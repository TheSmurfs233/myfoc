## 1. 职责边界

- **管**：过流、过压、欠压、堵转、超速、角度异常、ISR 超时的检测；封波动作；故障码记录与清除。
- **不管**：故障恢复后的控制策略（在 `app_state`）。

**安全原则**：任何保护动作的最终结果都是 **MOE=0 封波**（六路全关），
且**不允许自动恢复**，必须上位机/按键清除。

## 2. 接口

```c
/* User/Mid/mid_prot.h */
typedef enum {
    FAULT_NONE          = 0,
    FAULT_OC_HW         = 1u << 0,   /* 硬件过流（比较器/未实现） */
    FAULT_OC_SW         = 1u << 1,   /* 软件过流（ADC 判断） */
    FAULT_OV            = 1u << 2,   /* 母线过压 */
    FAULT_UV            = 1u << 3,   /* 母线欠压 */
    FAULT_STALL         = 1u << 4,   /* 堵转 */
    FAULT_OVERSPEED     = 1u << 5,   /* 超速 */
    FAULT_ANGLE         = 1u << 6,   /* 角度传感器异常（SPI 错/跳变） */
    FAULT_ISR_OVERRUN   = 1u << 7,   /* 电流环超时 */
    FAULT_DRV           = 1u << 8,   /* 驱动器报错（nFAULT 引脚，若有） */
} fault_code_t;

void      prot_init(void);
void      prot_fast_check(const current_sample_t *cur, float vdc);  /* ISR 内，最快路径 */
void      prot_slow_check(void);                                     /* 主循环，1ms */
void      prot_trip(fault_code_t code);      /* 立即封波 + 记录 */
uint32_t  prot_get_fault(void);
void      prot_clear(void);                  /* 需无故障源才允许 */
uint8_t   prot_is_faulted(void);
```

### 3.2 硬件过流：当前引脚约束与可选方案

**约束**：LQFP32 上 **PA6 已被 ADC2_IN3 占用（B 相电流采样），
TIM1_BKIN 无可用外部引脚**。因此"外部比较器输出 → BKIN 引脚"这条路走不通。

可选方案对比：

| 方案 | 做法 | 响应 | 改动 | 评价 |
|---|---|---|---|---|
| **A. 纯软件** | FOC ISR 里比较三相电流 → 超阈值直接 `MOE=0` | ≤50µs | 无 | ✅ **先做这个** |
| B. G4 内部比较器 | COMPx 输入接 INA240 输出，COMP 输出经内部路由触发 TIM1 break | <1µs | 需改 CubeMX + 查 RM0440 的 COMP→TIM break 路由是否存在 | 最优，但【TBD】需查证 G4 是否支持 |
| C. 外部比较器 + 关断驱动器 | 比较器直接拉驱动器的 EN/SD 脚，绕过 MCU | <1µs | 改硬件 | 硬件方案，最可靠 |
| D. 增加 nFAULT 输入 | 驱动器 nFAULT → 任一空闲 GPIO 中断 | 取决于驱动器 | 改引脚 | 只对带保护的驱动器有效 |

【TBD】当前先实现 **方案 A**；方案 B/C 需用户确认硬件后决定。

### 3.3 软件过流的实现要点

```c
/* 在 FOC ISR 里，紧跟电流换算之后，PI 之前 */
if (fabsf(ia) > I_TRIP || fabsf(ib) > I_TRIP || fabsf(ic) > I_TRIP) {
    bsp_pwm_enable(0);             /* 立即 MOE=0，六路全关 */
    prot_trip(FAULT_OC_SW);
    return;                        /* 本周期不再算 PI，避免积分器继续累积 */
}
```

**为什么用绝对值而不是矢量幅值**：单次比较、无开方，最快。
相电流峰值判据本身就能覆盖所有情况。

**为什么要在 PI 之前**：过流瞬间若继续积分，恢复时积分器满载会产生冲击。

### 3.4 封波的正确做法

```c
static inline void pwm_off(void)
{
    TIM1->BDTR &= ~TIM_BDTR_MOE;      /* 直接操作寄存器，约 2 个周期 */
    /* 或 HAL_TIM_PWM_Stop(&htim1, TIM_CHANNEL_ALL)，但内部有判断，慢 */
}
```

【TBD】需要确认 `OSSI` 的设置：
- `OSSI=DISABLE`（当前）→ MOE=0 时输出由 GPIO 决定，可能浮空
- `OSSI=ENABLE` → MOE=0 时强制输出空闲电平（`OCIdleState/OCNIdleState`）
- **建议改成 `OSSIE=ENABLE` + `OCIdleState=RESET` + `OCNIdleState=RESET`**，
  保证封波后六路确定拉低（下管全关，电机自由停车，不刹车）

### 3.5 故障处理流程

```
检测到故障
    │
    ▼
立即 MOE=0（ISR 内，微秒级）
    │
    ▼
记录故障码 + 记录现场快照（ia,ib,ic,id,iq,speed,elec,vdc）
    │
    ▼
状态机 → FAULT（主循环）
    │
    ▼
串口/日志上报（1 次，不要循环刷屏）
    │
    ▼
等待清除命令 → 检查故障源是否消失 → 允许清除 → IDLE
```

## 4. 时序/数据流

```
快速保护（20kHz，ISR 内）        慢速保护（1kHz，主循环）
├─ 相电流过流                    ├─ Vbus 过压/欠压
├─ 角度异常                      ├─ 堵转判断
└─ ISR 超时                      └─ 超速判断
        │                                │
        └────────────┬───────────────────┘
                     ▼
              prot_trip(code)
                     ▼
         MOE=0 + fault_code |= code
                     ▼
              app_state → FAULT
```

**分级原则**：能在 1 个 PWM 周期内造成损坏的（过流）放 ISR；
慢变量（Vbus、速度）放主循环，避免占用 ISR 时间。

## 6. 验证方法（S7 台架清单）

1. **软件过流**：临时把阈值调到很低（如 0.5A），轻加载，验证能在 1 个周期内封波，
   故障码正确，六路输出全部拉低（示波器确认）。
2. **虚假触发**：正常运行时大幅加速/减速，确认不误触发（阈值和滤波要合理）。
3. **清除流程**：故障后发清除命令，故障源未消失时应拒绝清除并回错误码。
4. **堵转**：手捏住转子给 iq 指令，应在设定时间内报堵转并封波。
5. **ISR 超时**：人为在 ISR 里加 60µs 延时，确认能报 FAULT_ISR_OVERRUN。
6. **上电安全**：复位瞬间到 `bsp_pwm_init()` 完成之间，六路必须是确定的低电平
   （靠 GPIO 复位默认态 + 驱动器使能脚），**用示波器确认没有窄脉冲**。

## 速度反馈的失效模式（S10 发现）

二阶 PLL 在真实转速超出捕获范围（约 ±170 rpm）后会**自由振荡**，
速度读数卡在最后的值（实测卡在 2000 rpm 限幅约 6 秒）。
这会让**堵转保护失效**（`|spd| < 30` 永不满足）。

**修复**（#134）：用 10 ms 窗口估计器做"是否在动"的判据——
`|win| < 15 rpm` 且 `|pll| > 300 rpm` 持续 50 ms → 清零 PLL 积分器。
`enc` 命令的 `guard = N` 显示该守卫动作次数。
