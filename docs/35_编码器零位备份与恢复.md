# 35 · 编码器零位备份与恢复

> 为什么需要这份记录：`align ol` 会在编码器有效时调用 `mid_enc_zero()`，
> **把当前角度写成新的电气零位**。如果新零位不如 S5 用双向扫频标定的那个准确，
> 需要能精确恢复。

---

## 1. 当前备份（2026-10-31 读取）

| 项 | 值 |
|---|---|
| **电气零位 `zero_deg`** | **131.91°** |
| 方向 `dir` | 0 |
| 来源 `src` | flash（`0x0801F000` 页，magic `ENC1`） |
| 读取时的机械角 | 215.81° |
| 读取时的电角度 | 70.66° |
| 原始码 `raw` | 15825 |
| CRC 状态 | ok，累计 0 错误 / 102285 帧 |

读取方式：

```bash
enc      # 最后一行 err = ... zero 131.91 deg, dir 0, src flash
```

---

## 2. 恢复方法

### 2.1 精确恢复（推荐）

```bash
enc zero 131.91
```

固件从 **#128 起**支持带参数的 `enc zero <deg>`（0~360），
直接写入指定零位并存 flash，不需要转动转子。

### 2.2 重新标定（备选）

```bash
mode 2
start
align          # S5 的双向扫频法，约 18 秒，误差约 ±5.3°
```

### 2.3 兜底

```bash
enc zero       # 把"当前转子位置"记为零位（前提：转子确实在机械零点）
```

---

## 3. 什么时候会改写零位

| 操作 | 是否改写零位 |
|---|---|
| `enc zero` | ✅ 写成"当前位置" |
| `enc zero <deg>` | ✅ 写成指定值 |
| `align`（扫频） | ✅ 用扫频结果覆盖 |
| `align ol`（开环预定位） | ❌ **不覆盖**（#129 起）：只打印坐标系偏移，不动零位 |
| `enc dir <0\|1>` | ❌ 只改方向 |
| 上电 / 重启 | ❌ 从 flash 加载，不改 |
