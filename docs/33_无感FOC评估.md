# 33 · 无感 FOC 评估

> 结论先行：**硬件支持"中高速无感"，低速需要 I/f 开环启动，零速不可行。**
> 不需要改板子；但有一个硬伤（没有相电压采样）和两个电机特性限制。

---

## 1. 硬件能力核对

| 无感 FOC 的需求 | 本板现状 | 结论 |
|---|---|---|
| 至少两相电流采样（与 PWM 同步） | ADC2 注入组 3 相，TIM1_CC4 峰顶触发，20 kHz | ✅ 完全满足 |
| 电流精度 | 25 mΩ + INA240A2，0.645 mA/LSB | ✅ 够用（量程 ±1.32 A 偏小） |
| PWM 分辨率与频率 | TIM1 中心对齐 20 kHz，ARR 4249 | ✅ 合理 |
| 母线电压 | ADC1_IN2，1 kHz | ✅ |
| **相电压采样** | **无**（只有 VBUS） | ⚠️ **必须用"指令电压 + 死区补偿"重建** |
| 运算能力 | 170 MHz M4F + FPU + CORDIC；FOC ISR 实测 6.5 µs / 50 µs | ✅ 余量充足（观测器约 +2~4 µs） |
| 编码器 | 有 MT6701 | ✅ **可作为无感的"真值"来标定/验证** |

**结论**：算力和采样都够；**唯一硬件缺口是没有相电压采样**，
所以只能用 `vα/vβ = f(占空比, Vbus)` 重建电压，精度受死区与器件压降影响。

---

## 2. 电机适配性（真正的限制在这里）

| 参数 | 值 | 对无感的影响 |
|---|---|---|
| 极对数 | 7 | 电频率 = 转速/60×7，1800 rpm 时 210 Hz |
| 反电动势常数 | 4.13 mV/(电 rad/s) | 1000 rpm 时相电压峰值约 3.0 V |
| 相电阻 R | 2.3 Ω | 低速时 `R·i` 项远大于反电动势 |
| 相电感 L | 0.5 mH | **L/R = 217 µs**，只有 4.3 个 PWM 周期 |
| 额定电压 | 12 V | 电压上限 5.7 V（调制比 0.95）→ 最高约 1880 rpm |
| 电流量程 | ±1.32 A | 堵转电流 3.5 A → 必须限流 |

### 三个关键限制

**① 低速时反电动势淹没在电阻压降里**

```
100 rpm 时：E ≈ 0.30 V，而 R·i（0.1 A）= 0.23 V
→ 反电动势只占测量电压的一小部分 → 角度估计噪声大
```

**② 没有凸极性 → 高频注入（HFI）不适用**

本机是表贴磁钢的云台电机，`Ld ≈ Lq`（无凸极）。
HFI 依赖 `Ld ≠ Lq` 的差异（通常 10~30%），本机差异很小。
**所以零速/极低速的无感要靠 I/f 开环拖动**，不能靠 HFI。

**③ 电感小 → 电流纹波大**

```
50% 占空比时：ΔI_pp = Vdc·T/(4L) = 12 × 50µs / (4 × 0.5mH) = 0.30 A
```

相对 ±1.32 A 量程是 23%。观测器要能容忍这个纹波（用平均值或低通）。

## 3. 无感 FOC 的原理

### 3.1 出发点是电机方程

在 αβ 静止坐标系下：

```
vα = R·iα + L·diα/dt + eα
vβ = R·iβ + L·diβ/dt + eβ
```

其中反电动势与转子角度直接相关：

```
eα = −ωe·ψf·sin(θe)
eβ = +ωe·ψf·cos(θe)        ψf = 永磁磁链
```

于是：

```
θe = atan2(−eα, eβ)
|e| = ωe·ψf   →  转速
```

**这就是全部原理**：从电流和电压里把 `eα/eβ` 抠出来，角度和转速就都有了。

### 3.2 怎么"抠"出反电动势：三种主流做法

| 方法 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| **反电动势观测器** | 用 `e = v − R·i − L·di/dt` 直接算 | 简单、快 | 对 `di/dt` 噪声敏感，需滤波 |
| **磁链观测器** | `ψ = ∫(v − R·i)dt`，再 `θ = atan2(ψβ, ψα)` | 不需要微分，噪声小 | 纯积分会漂移 → 要用低通/带补偿的积分；R 误差会累积 |
| **滑模观测器 SMO** | 用符号函数强制电流误差归零，取其等效控制量 | 对参数误差鲁棒 | 抖振（chattering），需要滤波 |

**工业上最常见的是"反电动势 + PLL"**：
不直接 `atan2`（噪声大、需要除法），而是把 `eα/eβ` 送进一个 PLL，
输出 `θ̂` 与 `ω̂` —— **和本项目 S8.1 里给编码器用的 PLL 完全同构**：

```
err ~ (−eα·cos θ̂ − eβ·sin θ̂)          ← 相位误差
ω̂ += ki·err·dt ;  θ̂ += (ω̂ + kp·err)·dt
```

好处：自动平滑、自动给出转速、对噪声不敏感。

### 3.3 零速为什么不行

```
e = ωe · ψf
```

转速为 0 → 反电动势为 0 → **没有任何转子位置信息**。
而且低速时 `R·i` 项和死区误差远大于 `e`。

**所以所有无感方案都必须解决"启动"**：

| 启动方式 | 做法 | 适用 |
|---|---|---|
| **I/f 开环拖动** | 按设定的频率旋转电流矢量，强制转子跟随；达到一定转速后切闭环 | ✅ 通用，本机首选 |
| HFI 高频注入 | 注入高频电压，用 `Ld≠Lq` 引起的电流响应估角度 | ❌ 本机无凸极 |
| 预定位 + 盲启 | 先对齐到已知角度再强拖 | 与 I/f 配合 |

### 3.4 切换（handover）是最难的一步

```
I/f 阶段：θ̂ 来自人为设定的斜坡，电流矢量跟着转
切换条件：估计角度与开环角度足够接近，且 |e| 已超过噪声
切换动作：把 θ̂、ω̂ 平滑地交给观测器（常见做法是逐渐减小开环电流、增大闭环权重）
```

切换瞬间最容易失步 → 需要"失步检测 + 退回 I/f"的保护逻辑。

## 4. 本板能做到什么程度

### 4.1 可实现的速度范围

| 转速段 | 可行性 | 做法 |
|---|---|---|
| **0 ~ 约 100 rpm** | ❌ 观测器不可用 | **I/f 开环拖动** |
| 约 100 ~ 300 rpm | 🟡 勉强 | 反电动势约 0.3~1.0 V，需死区补偿 + 滤波 |
| **300 ~ 1800 rpm** | ✅ 可行 | 反电动势 1.0~6.0 V，信噪比足够 |

依据：反电动势 4.13 mV/(电 rad/s)，
300 rpm 时 `E ≈ 0.9 V`，而估算的电压重建误差约 0.05 V（死区）+ 0.05 V（器件压降）→ 信噪比约 10:1。

### 4.2 精度预期（对比有感）

| 项 | 有感（现状） | 无感（预期） |
|---|---|---|
| 角度精度 | 0.022° 分辨率、±0.1° 精度 | 估计误差约 ±1~3°（取决于补偿） |
| 最低转速 | 30 rpm | 需 I/f，切换前无闭环 |
| 速度纹波 | 11 rpm @800 rpm | 会变差（角度噪声 → 转矩脉动） |
| 转矩脉动 | 10~14 mA | 可能升到 30~50 mA（死区/角度误差） |

**无感的主要代价**：角度误差 → Park 变换失配 → 转矩脉动与效率下降。

## 5. 如果要实现，路线图

| 步骤 | 内容 | 验证方式 |
|---|---|---|
| **S10.1** | 电压重建：`vα/vβ = (duty − 0.5)·Vbus`，加死区补偿 | 与实测相电压对比（需示波器） |
| **S10.2** | 反电动势观测器 + 复用 `alg_pll` 输出 θ̂/ω̂ | **拿编码器当真值**，统计角度误差 |
| **S10.3** | I/f 开环启动 + 切换逻辑 | 从静止启动到 500 rpm 不失步 |
| **S10.4** | 失步检测与退回 | 人为堵转/加速，验证能退回 I/f |
| **S10.5** | 全速域对比测试 | 有感 vs 无感：纹波、效率、最高转速 |

**最大优势**：本项目**有编码器**，可以在同一套硬件上把无感算法的角度误差
直接量化出来（`enc` 的机械角 vs 观测器输出），这在纯无感产品上是做不到的。

### 工作量估计

| 项 | 量级 |
|---|---|
| S10.1 电压重建 + 死区补偿 | 小（半天） |
| S10.2 观测器 + PLL | 中（1~2 天，含整定） |
| S10.3 I/f + 切换 | 中偏难（最容易反复的一步） |
| S10.4 保护 | 小 |
| 总计 | **约 3~5 天**，且低速段需要反复试 |

## 6. 结论

| 问题 | 答案 |
|---|---|
| 硬件支持无感 FOC 吗？ | **中高速支持**（300~1800 rpm）；低速需要 I/f 启动；零速不可能 |
| 需要改板吗？ | **不需要**，但"无相电压采样"会让精度打折 |
| 电机适合吗？ | 部分适合：无凸极 → HFI 不可用；L/R 小 → 观测器离散化要小心 |
| 值得做吗？ | 如果目标是**去掉编码器降成本**，值得；如果只是好奇，现有有感方案性能更好 |
