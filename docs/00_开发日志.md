### 关键设计

**幅值斜坡放在模块内部**：`alg_if_step()` 自己把 `i_now` 从 0 升到 `i_amp`（100 ms）。
原因是开环预定位存在 **180 度电角度歧义**（实测两个稳定位置相距 27.4 机械度），
硬给电流会让转子"顶"在错误的一侧，缓升才能让它滑入同步。

**I/f 期间速度环必须关闭**（`app_spd_off()`）——此时没有可信的速度反馈。

**编码器检查按需跳过**：I/f 启用时跳过"20 帧无有效帧 / 200 帧卡零"判定，
否则无编码器时一启动就 FAULT。

## 2026-10-31 · 撤回静止检测，改为"离开 RUN 时清零 PLL"（#136）

### #135 的真机后果（严重）

发 `spd 300` 后速度反馈一直是 0、`guard` 计数从 7 涨到 11，
速度环据此把电流拉满 → **过流保护跳闸**（`oc` 计数 +1）。

### 根因：静止检测与 PLL 的 gap 路径互相踩

```c
/* PLL 块：帧间隔 >= 2 ms 时走 gap 分支 */
} else { alg_pll_reset(&s_pll, elec); }   /* 保留 omega，且不更新 spd_rpm */
```

IDLE 时帧间隔正好 ~2 ms -> 每次更新都走 gap 分支：`spd_rpm` 冻结在旧值，
静止检测看到"PLL 说在转 + 转子静止" -> 反复触发 -> 速度环读到 0 ->
积分饱和 -> 电流顶到限幅 -> 过流。

### 最终方案：只在状态切换时动作

```c
void mid_enc_pll_clear(void);   /* 清 omega + 角度对齐 + 速度归零 */
```

调用点：`app_stop()`（stop / 模式切换）、`app_fault_raise()`（故障后桥臂关断）。

**为什么安全**：只在状态切换瞬间执行一次，运行期间完全不介入 → 不可能误触发。

**代价**：运行中堵转（不经过状态切换）仍检测不到 —— 那是 master 的既有行为，
不是本次引入的回归。

### 保留的有价值改动

大间隔分支现在会清 `s_win_rpm`（原来留下冻结旧值）。

### 验证

| 项 | 结果 |
|---|---|
| Keil | 0E/0W，`Code=57374 RO=2474 RW=444 ZI=9988` |
| 主机测试 | **531/0 PASS** |
| 新增测试 | `pll_clear drops a free-running speed estimate`、`tracking is untouched while the motor turns` |

### 真机回归结果（PASS）

| 项 | 结果 |
|---|---|
| 300 rpm | 实测 299，iq 0.06 A，角度误差 -0.93 度 |
| 800 rpm | 实测 804，iq 0.07 A，角度误差 -1.52 度 |
| 1800 rpm | 实测 1797，iq 0.09 A，角度误差 +3.03 度 |
| stop 后 | 滑行结束立即归 0（修复前卡在 2000 rpm 约 6 秒） |
| 故障计数 | oc 0 / os 0 / st 0 / uv 0 / ov 0 / enc 0（无一次误跳闸） |

与 #133 的正常运转表现完全一致，证明改动无回归。

## 2026-10-31 · 修复守卫本身：改用"静止检测"而不是窗口读数（#135）

### 上一版（#134）为什么没生效

#134 用 `|win_rpm| < 15` 作判据，真机测试发现守卫**不动作**，
波形通道给出直接证据（转子已静止 5 秒）：

| 通道 | 值 |
|---|---|
| ch17 窗口估计器 | **1809.5 rpm（430 帧完全不变 = 冻结的旧值）** |
| ch18 PLL | 907 rpm（在变，说明 PLL 还在跑） |
| ch7 机械角 | 160.94 度（完全静止） |

根因：`mid_enc.c` 的"大间隔保护"在 `dt > 2 ms` 时会清空累加器，
而 **IDLE 状态下的慢速轮询正好是约 2 ms** -> 每次更新都被判为大间隔，
窗口永远凑不满 10 ms，`s_win_rpm` 一直保持旧值。
守卫位于"窗口完成"分支内部，因此**永远不执行**。

### 中间尝试（失败）

把阈值放大到 20 ms：窗口能更新了，但主机测试立刻抓到回归 ——
上一节"方向翻转"测试留下的巨大角度跳变被当成正常增量累加，
窗口算出 **−413 rpm**（应为 +600）。
**阈值不能简单放大**：2 ms 保护是为了挡住这类跳变。

### 最终方案

守卫**移出窗口块**，改为每次更新都执行的静止检测：

```c
if (|dm| < 0.2 度) { s_still_cyc += dt; } else { s_still_cyc = 0; }

if (s_still_cyc >= 50 ms && |spd_rpm| > 300) {   /* 静止但 PLL 说在转 */
    pll.omega = 0;  alg_pll_reset(&pll, elec);  spd = 0;
}
```

**阈值依据**：编码器 14 bit（0.022 度/LSB），0.2 度约 9 个码；
30 rpm 的最低工作转速在 1 ms 内移动 0.18 度，仍低于阈值 —— 但那是低转速，
第二个条件 `|spd| > 300 rpm` 不成立，所以**正常运转不会误触发**。

### 同时修掉的另一个缺陷

大间隔分支原来只清累加器、**不清 `s_win_rpm`**，留下冻结的旧值误导所有消费者。
现在会一并清零（这也是暴露本 bug 的直接线索）。

### 验证

| 项 | 结果 |
|---|---|
| Keil | 0E/0W，`Code=57378 RO=2474 RW=448 ZI=9992` |
| 主机测试 | **530/0 PASS**（守卫触发 / 真实转动不触发 两条都在） |
| 主机回归 | `enc: speed estimate over a 10ms window` 恢复通过（+600 rpm） |

> 真机回归待烧录：#135 后 `stop` 滑行停止应在 **50~100 ms** 内把速度归 0。

## 2026-10-31 · 修复：速度 PLL 失去锁定时会"自由振荡"（#134）

### 发现过程

在验证 #133 的观测器标定后做收尾检查时发现：`stop` 之后桥臂已关断、
转子机械位置**完全不动**（连续两次读数都是 214.4 度），但速度读数仍停在
**2000 rpm**（正好是 `w_max` 限幅），持续约 6 秒才慢慢衰减。

实测序列（转子已停）：

| 时间 | 机械位置 | 速度读数 |
|---|---|---|
| 5.67 s | 214.4 度 | 1999.6 rpm |
| 7.29 s | 214.4 度 | 1937.8 rpm |
| 9.74 s | 214.4 度 | 1877.9 rpm |

### 原因

二阶 PLL 的固有缺陷：角度输入静止时，`theta_hat` 仍按 `omega_hat` 累加，
相位误差变成锯齿波，一个周期内正负抵消 → 积分器输入平均为 0 → `omega` 不衰减。
当真实转速与估计值之差超出捕获范围（约 ±20 Hz 电频率 = ±170 rpm）时，
环路**无法把速度拉回来**，会一直自由旋转。

### 危害

| 场景 | 后果 |
|---|---|
| **堵转** | 速度读数仍是 1500~2000 rpm → 堵转保护（`\|spd\| < 30`）**永远不触发** |
| RUN 状态下静止 | 会**误报超速**（读数撞到 2000 rpm 的限幅） |
| `stop` / 故障后 | 速度读数虚假 |

> 这是既有（S8）代码的问题，不是 S10 引入的；S8 的验收都是让电机"平滑减速"，
> PLL 一直跟得上，所以没暴露。

### 修复：动作检测守卫

窗口估计器（10 ms 角度增量之和）对"是否在动"是**无歧义**的，用它做判据：

```c
if (|win_rpm| < 15 && |pll_rpm| > 300 持续 50 ms) {
    pll.omega = 0;              /* 清积分器 */
    alg_pll_reset(&pll, elec);  /* 角度锁到实测值 */
    spd = 0;
}
```

**阈值依据**：速度环最低工作转速是 30 rpm，`15 rpm` 留了一倍余量，
正常运转时窗口读数不可能低于它 → 守卫不触发。

### 对现有功能的影响（**正常路径零改动**）

| 工作状态 | 守卫 |
|---|---|
| 正常运转 30~1800 rpm | 不触发 |
| 加速 / 减速 / 斜坡 | 不触发 |
| 上电静止 | 不触发（PLL 也不 >300） |
| 堵转 | 触发 → 速度归 0 → 堵转保护正常工作 |
| stop 后滑行停止 | 触发 → 读数归 0 |

### 验证

- **主机测试**（新增 5 条）：
  - `enc: lost-lock guard clears a free-running PLL` —— 模拟 1460 rpm 后静止，守卫触发且读数 <50 rpm；
  - `enc: the guard stays quiet while the motor really turns` —— 持续真实转动时守卫**一次都不触发**。
- Keil 0E/0W `Code=57378 RO=2474 RW=444 ZI=9988`；主机 **530/0 PASS**。
- `enc` 命令新增一行 `guard = N pll resets`，便于真机确认守卫动作。

> 真机回归（正常转速不变 + 堵转能归零）待烧录后进行。

### 实验链条：一个假设、三次否定、最终定量

**① 初始测量（#130）**：误差 7.12 / 7.37 / 8.48 / 10.07 / 11.94 度（300..1800）。
特征：系统性正偏差、随转速增大。

**② 假设：反电动势低通的相位滞后**。
计算：1500 Hz 低通在 210 Hz 电频率滞后 8 度，加上一个 PWM 周期 3.8 度。

**③ 实验否定（#131）**：

| 配置 | 1800 rpm 误差 | 结论 |
|---|---|---|
| baseline | 11.93 | 基准 |
| lpf 关掉 | 16.12 | 更差 -> 低通不是误差源，它在压制噪声 |

| comp 1（超前） | 37.27 | 方向错 + 有 bug |

**④ 发现 bug（#132）**：补偿直接改了 LPF 的状态变量，每拍叠加。
改为只旋转临时副本后，方向实验给出明确答案：

| comp | 500 | 800 | 1800 |
|---|---|---|---|
| 0（不补偿） | 7.26 | 9.05 | 11.93 |
| 1（超前） | 9.83 | 15.01 | 25.12 |
| **2（滞后）** | **5.31** | **3.20** | **−1.29** |

**补偿方向是"滞后"**，与直觉相反 —— 主导效应是 v/i 采样时序，不是滤波。

**⑤ 定量拟合**：把误差当作 `err(ω) = e0(ω) − 57.3·Δdelay·ω + Δtrim`，
用三组 (delay, trim) 的实验数据反解出最优 `delay = 0`、`trim = −3.6 度`，
实测 worst = **2.19 度**（另一组 trim −2.5 为 3.35 度，验证了模型）。

> 期间我自己错了两次：
> (a) 把 trim 的符号搞反，推出 `delay 170 / trim −7.8`，实测 worst 16 度；
> (b) 没意识到补偿只作用于 e 的副本，误以为可以靠"负延迟"外推。
> 两处都靠**实测数据立即否定**，没有把错误结论写进代码。

## 2026-10-31 · S10.1 观测器基础设施（影子模式，固件 #130）

### 新增

| 文件/项 | 内容 |
|---|---|
| `User/Alg/alg_obs.c/.h` **新增** | 反电动势估计 `e = v - R*i - L*di/dt`、一阶低通、旋转到估计坐标系得 `ed/eq`、PLL 输出角度与转速 |
| `alg_pll_step_err()` | PLL 增加"直接喂误差"的入口：观测器的误差是 `\|e\|*sin(dθ)` 而不是角度，不能用角度环绕版本 |
| `alg_foc` | 暴露 `i_alpha/i_beta`、`v_alpha/v_beta`（观测器输入，按 `docs/34` 2.2 直接用控制器输出，不重建） |
| `obs` 命令 | `obs` 显示 `eα/eβ/ed/eq/θ̂/ω̂/角度误差/locked`；`obs on/off`、`obs bw <hz>`、`obs r <ohm>`、`obs l <mH>` |
| 波形 ch19/ch20 | 观测器电角度、与编码器角度差 —— **影子验证的核心** |
| `OBS_LPF_HZ` / `OBS_PLL_WN_HZ` / `OBS_W_MAX_RADS` | 初值 1500 / 80 / 2000 rpm 电角速度 |

### 关键设计点

**① 误差符号**：`ed = eα·cosθ̂ + eβ·sinθ̂ = |e|·sin(θ̂ − θe)`。
`θ̂ > θe` 时 `ed > 0`，要让 `θ̂` 减小 → PLL 必须喂 **`−ed`**。

**② 影子模式**：`s_obs_on` 默认 0，观测器只在 `obs on` 后运行，
且**不参与任何控制**（Park 角度仍来自编码器）。

**③ 启动时用编码器角度初始化**（有编码器时），避免长时间摆动。

### 过程中踩到的两个坑

**`WAVE_CH` 加到 21 但 `VOFA_MAX_CHANNELS` 还是 20** → `vofa_send()` 直接拒绝，
**每一帧都被丢弃**（主机测试报 `TX(0) = ""`）。已把上限提到 24。

**新增的 `obs` 帮助文本被合并进了 `align` 那一次 `log_printf`**，
导致帮助行数仍是 42（`doc_check` 要求 43）。已拆成独立一行。

## 2026-10-31 · S10.0 真机验证（#129）：零位保持 + 发现 180 度对齐歧义

### 修复确认

| 项 | 结果 |
|---|---|
| `clr` 清编码器计数 | ✅ crc 归零（#129 起 `mid_enc_clear_errs()` 生效） |
| **`align ol` 不改写零位** | ✅ 连续 3 次后 `zero` 始终 131.91 |
| 坐标系偏移打印 | ✅ `forced frame offset 346.58 deg (elec)` |

### 新发现：开环预定位的 180 度电角度歧义

实测三次对齐的原始码：`2436 / 1192 / 1187`。
`#2` 与 `#3` 差 5 码（0.1 机械度），但 `#1` 与它们差 **1249 码 = 27.4 机械度**。

```
27.4 机械 x 7 极对 = 191.8 电角度  ~= 180 电角度
180 电角度 / 7 = 25.7 机械度        （理论间距）
```

**这是永磁电机的固有现象**：转子的 N/S 两个磁极都能与外加矢量"对齐"，
所以存在两个稳定位置，相距 180 电角度（本机 25.7 机械度）。
转子被离它更近的那个磁极吸住，因此对齐结果取决于起始位置。

**不是 bug**，任何"固定矢量预定位"方案都有此问题。

### 对 S10 的影响与对策

| 用途 | 影响 |
|---|---|
| 写编码器零位 | ❌ 已不做（#128 的教训），歧义也就无关 |
| **I/f 开环启动** | 🟡 需处理：若停在 180 反侧，起步瞬间力矩反向 |

I/f 的标准对策（已写入 `docs/34` 的 S10.4）：

1. 电流幅值**缓升**，不是一步给满；
2. 起始频率极低（2 Hz）、加速很慢；
3. 转子会在 1~2 个电周期内被"拖入同步"，初始 180 度不影响最终同步；
4. 切闭环前必须确认观测器已收敛（S10.5 的切换条件）。

**结论**：`align ol` 的定位是"把最坏情况从任意角度收敛到 ±180 度内"，
剩余的同步由 I/f 的拖入能力解决。

### 发现的问题：`align ol` 覆盖了零位（设计错误）

实测：5 次对齐后 `zero` 从 **131.91 -> 234.01**。换算：

```
234.01 - 131.91 = 102.1 机械度
102.1 x 7 = 714.7 电角度 -> mod 360 = 354.7 deg = -5.3 deg
```

**-5.3 deg 正好是 S5 双向扫频的标定精度**，说明：

1. `alg_svpwm(theta=0)` 与 Park 的 θ=0 **是同一个方向**（两套坐标系一致）；
2. 转子被拉过去后**差约 5 deg 没到位**（齿槽/摩擦的平衡点），不是坐标系问题；
3. 若把该位置写成零位，会让编码器路径**变差 5 deg**。

**修正**：`align ol` 不再调用 `mid_enc_zero()`，改为**打印观测到的坐标系偏移**

> 零位已当场用新的 `enc zero 131.91` 恢复，并确认 `enc` 回到 `mech 102.10 / elec 354.69`。

实测清空后 `err = 4247/643871 crc` 仍是 4247，导致无法测量"某段时间内的 CRC 错误率"。
新增 `mid_enc_clear_errs()`，`clr` 现在会一并清零 crc/ovr/late/io（`frames` 继续累加，便于算比率）。

### 关于那 4247 个 CRC 错误

说明它们是之前积累的 —— 大概率是 5 次 `align ol` 把转子"砸"到位时的电流冲击引起的 EMI，
与已知的"开关噪声影响 SPI"一致；坏帧会被丢弃，不影响控制。

## 2026-10-31 · S10.0b 参数护栏（编译期断言 + 关键参数快照）

### 为什么加

S10.0a 重构时把加速度前馈写成了 `J/KE_elec`（漏乘极对数，**大 7 倍**），
而 Keil 依然 **0 Error / 0 Warning，`Code` 字节数也完全不变**——
浮点常量写错，编译器与字节数都发现不了。

### 三道护栏

| 层 | 实现 | 拦截时机 |
|---|---|---|
| **编译期** | `motor_cfg.h` 的 `MOTOR_CFG_ASSERT(...)`（负数组技巧） | 编译不过 |
| **主机测试** | `cfg: motor parameter golden values`（12 条断言） | `test/host` 失败 |
| **文档约定** | `docs/README` 维护约定：纯重构不能只靠编译通过验证 | 人工审查 |

### 编译期断言的写法（ARMCC 5 的限制）

ARMCC 5 **没有 `_Static_assert`**，而且**拒绝在数组长度里用浮点常量表达式**：

```c
/* 第一版这样写 -> error #31: expression must have integral type */
MOTOR_CFG_ASSERT((MOTOR_KT_NM_A > 0.020f) && (MOTOR_KT_NM_A < 0.045f), kt);
```

解决：把参数的**基准值写成整数**（mΩ / µH / µV·s·rad⁻¹ / n·kg·m² / mA），
浮点视图由它们派生，断言只做整数运算：

```c
#define MOTOR_KE_UV_RADS   4130        /* uV per elec rad/s */
#define MOTOR_KT_UNM       (MOTOR_KE_UV_RADS * MOTOR_POLE_PAIRS)      /* 28910 */
#define MOTOR_FF_ACC_U     ((MOTOR_J_NKGM2 * 1000L) / MOTOR_KT_UNM)   /* 3113  */

MOTOR_CFG_ASSERT((MOTOR_KT_UNM > 20000) && (MOTOR_KT_UNM < 45000), kt);
MOTOR_CFG_ASSERT((MOTOR_FF_ACC_U > 2000) && (MOTOR_FF_ACC_U < 5000), ff_acc);
```

顺带的好处：参数值不再有歧义（2.3 Ω 就是 2300 mΩ）。

### 负向验证（证明护栏真的会拦）

把 `MOTOR_KE_UV_RADS` 临时改成 0：

```
KEIL=2  (编译失败)
  motor_cfg.h(86): error: #94: the size of an array must be greater than zero
  motor_cfg.h(92): error: #39: division by zero
```

恢复后重新构建：0E/0W，`Code=53778`；主机测试 **515/0 PASS**（新增 12 条参数快照）。

### 覆盖的参数

编译期断言 10 条：极对数、R、L、KE、J、`I_MAX ≤ 1.30 A`（ADC 量程）、
`I_TRIP > I_MAX`、转速范围、`Kt` 区间、加速度前馈区间。

主机快照 12 条：极对数、KE、L、电流环 kp/ki、速度环 kp/ki、I_MAX、I_TRIP、
RPM_MAX、`Kt`、加速度前馈。

## 2026-10-31 · 无感 FOC 实施方案确定（docs/34）

### 方案要点

三段式推进，每段可独立验收、失败可退回：

```
影子模式（观测器只测不控）-> I/f 开环启动 -> 切换进闭环无感
```

| 步骤 | 内容 | 验收门槛 |
|---|---|---|
| S10.1 | `alg_obs` 基础设施 + `obs` 命令 + 波形通道 | 不影响现有控制 |
| S10.2 | **影子模式量化角度误差**（关键关卡） | 500 rpm 以上 <5 度 |
| S10.3 | 观测器整定（PLL 带宽、R 值） | 误差最小且高速不抖 |
| S10.4 | I/f 开环启动 | 连续 10 次不失步 |
| S10.5 | 切换 + 闭环无感 | 300~1800 rpm 双向稳定 |
| S10.6 | 失步检测（两级降级）+ 保护适配 | 丢锁能自动退回 |

### 与早期路线图的两点重要修正

**① 取消"电压重建"**：SVPWM 注入的零序分量在三相等量叠加，Clarke 后完全抵消
（`(2/3)(v0 − v0/2 − v0/2) = 0`），所以控制器自己的 `vα/vβ`
与"占空比 × Vbus 重建再 Clarke"等价。直接用 `vα/vβ`，省一整步开发与验证。

**② 增加影子模式关卡**：观测器先只测不控，用编码器当真值统计角度误差，
达标后才允许接入控制。避免"算法没验证就去控制电机"导致无法区分是算法问题还是切换问题。

### 已确认的决策

1. 保留编码器，命令切换有/无感（编码器同时作真值参考）
2. 最低无感转速 300 rpm（以下 I/f 覆盖）
3. **不改硬件**（不加相电压采样、不加硬件过流）
4. **不合并回 `master`**，`feature/sensorless-foc` 长期独立

## 2026-10-31 · 无感 FOC 可行性评估（docs/33）

### 结论

- **中高速可行**（约 300~1800 rpm），低速需 I/f 开环启动，零速不可能
- **不需要改板**，但没有相电压采样 → 只能用"指令电压 + 死区补偿"重建
- 电机无凸极（表贴磁钢）→ **HFI 高频注入不适用**，只能 I/f 启动
- 运算能力够：FOC ISR 实测 6.5 µs / 50 µs，观测器约 +2~4 µs

### 关键数据

| 项 | 值 |
|---|---|
| 反电动势常数 | 4.13 mV/(电 rad/s)，1000 rpm 时约 3.0 V |
| L/R | 217 µs（仅 4.3 个 PWM 周期） |
| 50% 占空比电流纹波 | 0.30 A p-p（占 ±1.32 A 量程 23%） |
| 电压重建误差 | 死区约 0.05 V + 器件压降约 0.05 V |

### 原理要点（写入 docs/33）

`eα = −ωψf·sinθ`、`eβ = +ωψf·cosθ` → `θ = atan2(−eα, eβ)`、`|e| = ωψf`。
工程上不直接 atan2，而是把 eα/eβ 送进 **PLL**（与本项目 S8.1 的编码器 PLL 同构），
同时得到平滑的角度与转速。三种取 e 的方法：直接反电动势、磁链积分、滑模观测器。

## 2026-10-28 S8.1 + S8.2 · PLL 速度观测器（纹波再降 2.5~3 倍）

### 为什么做

10 ms 窗口测速的延迟约 15 ms，把速度环带宽压在 1~3 Hz；
S7 末尾遗留的 6.7 Hz / 约 4% 转速脉动就是它的直接后果。

### 实现

| 文件 | 内容 |
|---|---|
| `User/Alg/alg_pll.c/.h`（新增） | 二阶 PLL：`err = wrap(θm−θ̂)`、`ω += ki·err·dt`、`θ += (ω+kp·err)·dt`；参数按 `kp=2ζwn`、`ki=wn²` 换算 |
| `User/Mid/mid_enc.c` | 每帧把**电角度**送进 PLL；`spd_hz/spd_rpm` 可由 PLL 或窗口输出（`mid_enc_set_spd_src`） |
| `board_cfg.h` | `PLL_WN_HZ = 14`、`PLL_ZETA = 0.707`、`ENC_SPD_DEFAULT = PLL` |
| `app_cmd.c` | `pll on/off`、`pll wn <hz>`、`pll zeta <v>`；`pll` 命令显示两种测速的实时值 |
| 波形 | 新增 ch17（窗口测速）、ch18（PLL 测速）用于对比，`WAVE_CH` 17 -> 19 |

|---|---|---|
| 8 Hz | 0.15 A | 43 rpm |
| 12 Hz | 0.05 A | 8 rpm |
| **14 Hz（采用）** | **0.06 A** | **11 rpm** |
| 20 Hz | 0.09 A | 18 rpm |
| 40 Hz | 0.13 A | 35 rpm |
| 100 Hz | 0.15 A | 44 rpm |

14 Hz 恰好落在两者之间。

```
转速 52 -> 撤销 kick -> 力矩掉到 0.05 A -> 落回 48

```

**② 起步瞬间速度飙高**

`spd 50` 的第一帧误差 50 rpm -> `Kp*50 = 0.8 A`，
加速度 = Kt*I/J = 2930 rpm/s，17 ms 就冲过目标，
而速度反馈是 10 ms 窗口（约 5 ms 延迟），PI 来不及反应。

### 修复（三步）

**1. kick 改为时间窗口 + 静止判定**

```c
/* 目标改变后 250 ms 内，且转子仍停着（|spd| < 10 rpm）才施加 */
if ((kick_on) && (|spd| < 10)) -> 至少 0.20 A
```

只加时间窗口不够：kick 在 250 ms 内持续 0.20 A，加速度约 690 rpm/s，
对 30 rpm 的目标会冲到 128 rpm（实测）。加上静止判定后立刻撤销。

**2. 速度参考加加速度限制（600 rpm/s）**

```c

step = 600 * 0.001 = 0.6 rpm/ms
```

**3. `spd` 命令显示 target 与 ramped ref**

## 2026-10-27 S7.2 · 反电动势前馈 + dq 解耦（含实测结论修正）

### 实现

```c
vd = PI_d(e_d) - g*w_e*L*iq
vq = PI_q(e_q) + g*w_e*L*id + g*K_emf*w_e
```

| 项 | 值 / 说明 |
|---|---|
| `K_emf` | **4.13 mV/(elec rad/s)**，由 KV 反推（330 rpm/V → 3.03 mV/rpm，`w_e = rpm*0.733`） |
| `L` | 0.5 mH（假设值，影响很小：1500 rpm 时解耦项只有反电动势的 0.4%） |
| `g` | 运行时可调（`ff <0..1>`），并带转速门限 |
| 转速门限 | `\|w_e\| < 100 rad/s` 关闭，`> 300 rad/s` 全开 |

`w_e` 取自编码器 `spd_hz*2π`，**带符号**，反转时前馈符号自动正确。

### 单元测试（467/0 PASS，新增 7 条）

- 静止时前馈为 0；
- `w_e = 1000 rad/s` 时 `vq = 4.00 V`（`K_emf*w_e`）；
- 反转 `w_e = -1000` 时 `vq = -4.00 V`；
- `ff 0` 时完全不作用；
- 解耦项：`theta=90°`、`iq=-0.3`、`L=1 mH`、`w_e=1000` → `vd=+0.30 V`，与手算一致。

### 硬件实测（重要修正）

**① 低速（12 Hz 电频率）：前馈反而变差**

| 配置 | rise | ripple |
|---|---|---|
| `ff 0` | 0.20 ms | 14~15 mA |
| `ff 1` | 0.25 ms | 31 mA |

原因：`w_e` 来自 10 ms 窗口的速度估计，低速（尤其齿槽造成的转速脉动）下噪声大，
前馈把这个噪声直接注入了 vq。**因此加了转速门限**（100/300 rad/s 淡入）。

**② 高速（235 Hz 电频率）：前馈无法改善**

```
w_e = 1477 rad/s -> 反电动势 = 0.00413 * 1477 = 6.1 V > 5.7 V 上限
```

此时整个电压预算都被反电动势占用，`m = 0.95` 恒定饱和，前馈也好、PI 也好都没有余量。
实测 `iq` 0.30 的参考只能维持 0.10~0.12 A（`ff 0` 与 `ff 1` 差别 <20%）。

**结论修正**：此前方案里写的"前馈能让高速 iq 保持 0.20 以上"是错的——
**高速的上限由供电电压决定，不由控制结构决定**。
前馈真正的价值在两处：

1. **动态**：电压饱和后恢复时，PI 积分不用重新"攒"反电动势，扭矩响应更快；
2. **解耦**：高速加速时 `id` 的摆动（曾测到 ±0.35 A）会被抑制。

这两点要等 **S7.3 速度环闭环**（频繁变速、进出饱和）才能测出收益。

**验证**：Keil 0E/0W `Code=44094 RO=2182 RW=288 ZI=9512`；主机 467/0 PASS

## 2026-10-25 S6-prep · 编码器改 SPI RX DMA，实测与踩坑（#66~#74）

## 2026-10-25 S5-align2 · 零位标定迭代到可用精度（#55 ~ #63）

**目标**：找到转子 d 轴与 A 相轴的对应关系（电角度零点）。

**试过的 4 种方法**（全部真机验证）

| # | 方法 | 结果 | 原因 |
|---|---|---|---|
| 1 | 固定 d 轴矢量 0.5A | 转子只动 0.83° | `T ∝ sin(Δθ)`，接近平衡点时力矩不足 |
| 2 | 固定矢量渐变到 1.0A | 只动 0.27° | 加力矩无效 |
| 3 | 旋转 + 急停 / 减速 | 落点散布 ±9.4° 机械 | 停下时带滞后角，静态力矩拉不动 |
| 4 | **双向扫掠平均** | **±1.9° 机械（±13.5° 电）** | 可用 |

**方法 4 的原理**：不追求"吸住转子"，而是**测量平均跟踪误差**——
正转 7 个电周期、反转 7 个电周期，每帧累加 `err = 编码器电角度 − 磁场电角度`。
摩擦滞后在两个方向符号相反自动抵消，偏心与齿槽波动被整圈平均掉，
剩下的平均值就是零点偏差，最后 `zero += err_mean / 7`。

**踩到的关键坑**：扫掠圈数必须是**整数机械圈**。
最初用 4 个电周期（= 0.57 机械圈），散布 ±40° 电角度；
改成 **7 个电周期 = 整整 1 机械圈**后降到 ±13.5°。
原因：编码器偏心误差的周期是 1 个机械圈，非整数圈平均不掉。

**再进一步**：扫掠加长到 **14 电周期 = 2 机械圈**后，
5 次取余散布从 3.87° 机械降到 **1.52° 机械 = 10.6° 电角度（±5.3°）**，
对应 FOC 转矩损失 0.4%，**定稿**。代价是对齐时间 7.2s → 14.2s。

**验证**：主机 408/0 PASS（含"扫掠能测出 49.04° 偏移并修正 7.006°"的仿真用例）；
Keil 0E/0W，`Code=38298 RO=2046 RW=236 ZI=9252`。

## 2026-10-25 S5-align · 强制对齐求电角度零点（#55）

**背景**：`enc zero` 只是"把当前位置记成 0"的相对零点，和转子磁极、A 相轴无关；
FOC 的 Park 变换要求 `elec = 0` 时转子 d 轴正好在 A 相轴上。
`docs/10` §5 的状态机里本来就有 **ALIGN**，这次把它实现了（S5 的最后一块）。

**实现**

```
mode 1 → start → align
  1. 输出 θ_force = 0 的固定矢量，m = 0.20 → 线电压约 1.5V，电流约 0.33A
  2. 每帧（20kHz，task_adc 里）比较编码器角度，< 0.5° 持续 200ms 视为稳定
```

|---|---|---|
| 过流 | 相电流 > 0.8 A | 封波 + FAULT |
| 超时 | 1.5 s 未稳定 | 封波 + IDLE，不写零位 |

- 固定矢量只在 `app_align_start()` 里写一次 CCR：矢量不变，没必要每帧重写

- `app_stop()` 会中止对齐；`app_set_mode()` 在 ALIGN 期间同样被拒绝；

## 2026-10-25 S4-perf4 · 使能 ART + 探针跟随 prof 开关（#38 / #39）

**#38：使能 ART**

新增 `User/Bsp/bsp_sys.c`，`app_init()` 最先调用：

```c
FLASH->ACR |= (FLASH_ACR_PRFTEN | FLASH_ACR_ICEN);
```

|---|---|---|
| `comp` 最小 | 7.9 µs | **7.2 µs**（−9%） |
| `pick` 最大 | 52.4 µs | **17.3 µs**（−67%） |
| `wr` | 2.5 µs | 2.5 µs（外设写，ART 无关） |

结论：ART 主要改善**取指与调度延迟**，`comp` 的 7.2µs 主要来自指令执行本身
（约 2.2 周期/指令，对带分支的浮点代码属正常），**不是瓶颈**，保留即可。

## 2026-10-25 S4-perf3 · phase 改成"同帧分段耗时"（#37）

**问题**：#36 的三个数 `conv 4.7 / vf 10.5 / ccr 12.8` 加起来 **12.8µs**，
可主循环周期只有 **7.7µs**（129kHz）—— 数学上不可能是同一帧。
根因是三个标记各自**独立取最小**，min 之间不可相减。

**改动**：把探针语义从"距中断的绝对时间"改成"**相邻阶段的耗时**"，

```
t_ref ──pick──► t_pick ──comp──► t_comp ──wr──► t_wr
```

| 标记 | 区间 |
|---|---|
| `pick` | 中断入口 → 主循环取走该帧（调度延迟） |
| `comp` | 取走 → V/f + SVPWM 算完 |
| `wr` | 算完 → CCR1~3 写完 |

**顺带确认**：查表后 `vf − conv` 从 8µs 降到 **5.8µs**，
说明删掉探针里的 64 位除法（#36）确实回收了约 2µs。

**验证**：Keil **0E/0W**，`Code=33442 RO=1866 RW=152 ZI=9152`；主机 **350/0 PASS**。

## 2026-10-25 S4-perf2 · phase 探针去掉 64 位除法（#36）

## 2026-10-25 S4-perf · phase 参考时间戳快照 + SVPWM 查表（#35）

**背景**：`phase` 的 min/max 出现 `ccr min(6µs) < vf min(12µs)` 这种不可能的组合，
而 `conv→vf` 相差 8µs，怀疑是三次 `cosf()` 的开销。

**A. 参考时间戳每帧快照**

原来每个 mark 都读全局的 `bsp_adc_isr_cyc()`；如果处理途中又进了一次 ADC 中断，
参考就被刷新，后面的 mark 会算出偏小的值（这就是 `ccr < vf` 的由来）。
现在 `task_adc()` 开头快照一次 `t_ref`，本帧所有 mark 都用它 → min/max 同帧可比。

**B. `alg_svpwm` 的 cos 换成 256 点查表 + 线性插值**

| | 之前 | 之后 |
|---|---|---|
| 三角函数 | 3 × `cosf()`（约 6~8µs） | 3 次查表 + 插值（<1µs） |
| 精度 | 精确 | 误差 **0.0075%** = **0.3 PWM count**（1 count = 2.82mV） |
| Flash | — | +1KB 表（RO-data 870→1866），`cosf/sinf` 不再链接，Code 少 624B |

**验证**
- Keil **0E/0W**，`Code=33398 RO=1866 RW=152 ZI=9152`
- 主机 **350/0**（新增"查表 vs cosf"逐点对拍：720 点最大偏差 < 1 个 PWM count）
- 预期 `phase`：`conv ≈4µs`、`vf ≈5µs`（原 12µs）、`ccr ≈6µs`（原 16µs）

## 2026-10-25 S4-fix2 · CCR 预装载落到代码 + phase 探针改成 DWT 时差（#33 / #34）

| `User/Bsp/bsp_adc.h/.c` | 新增 `bsp_adc_isr_cyc()`（中断入口的 DWT 时间戳） |

## 2026-10-25 S4-fix · 相位探针 + 移除 UART DMA 覆盖（#32）

**背景**：用户问"能不能确定每个关键点在 50µs 里落在什么位置"，并已在 CubeMX 把
UART RX DMA 改成 CIRCULAR、把 PWM 通道的 Output compare preload 勾上。

**已确认**
- `usart.c` 已生成 `DMA_CIRCULAR`（16:04）→ **删掉 `bsp_uart_init()` 里运行时改 CIRCULAR 的覆盖**，

**新增：`phase` 命令（控制链相位探针）**

`prof` 用 DWT 量"每段多久"，`phase` 用 **TIM1->CNT** 量"每点在周期里的位置"
（1 count = 11.76ns，4250 counts = 50µs，可直接和 `CCR4=4000` 的采样点比较）：

| 标记 | 采集位置 | 含义 |
|---|---|---|
| `isr` | ADC 中断入口（ISR 内锁存） | 采样时刻 |
| `conv` | 主循环换算完 | 电流可用 |
| `vf` | SVPWM 算完 | 可写 CCR |
| `ccr` | CCR1~3 写完 | 控制量落地 |

**为什么用 CNT 而不是 DWT**：DWT 是自由计数器，要知道"在周期里的位置"还得有周期基准
（多一个中断）；而 TIM1->CNT **本身就是**周期内的位置，精确且零开销。

| 电流 | **−335 / +169 / +157 mA** | 348 / 174 / 174 mA | 幅值 **−4%** |

**安全提示**（已写进 docs/13）：没有电流环/过流保护时，占空比差与电流的关系

## 2026-10-25 S1-fix4 · 波形"锯齿"：正弦表加线性插值

**现象**：用户反馈 VOFA+ 里波形有很多锯齿。

**分析**
测试正弦用的是 **64 点 int16 查表**。500Hz 采样、1Hz 正弦时，每个表值要重复约
`500/(64×1) = 7.8` 帧，画出来就是**阶梯**状 —— 这是测试信号本身的量化，不是链路问题。

**改动**（`app_main.c` `task_wave()`）

```c
/* 表间线性插值，消除 64 点台阶 */
pos  = s_wave_phase01 * 64.0f;
i0   = (uint16_t)pos;
frac = pos - (float)i0;
v0   = tab[i0];
v1   = tab[(i0 + 1) & 63];      /* 表是循环的 */
ch4  = v0 + (v1 - v0) * frac;
```

内存不变（还是 64×2B），每帧多 3 次浮点乘加（500Hz 下可忽略）。

**顺带整理"锯齿"的四种可能**（写进 15 号文档 5.2）：
1. 正弦阶梯 → 已修
2. `ch5` 主循环频率每 1s 才更新 → 正常，不想看就隐藏该通道
3. VOFA+ 的 `Δt` 设错（默认 1ms，实际 2ms@500Hz）→ 改成 2ms 或用 Auto
4. 丢帧造成的缺口 → 看 `stat` 里的 `drop`，涨了就 `rate` 降档

**验证**：主机 156/0 PASS；Keil 0E/0W，`Code=23350 RO=734 RW=68 ZI=8844`

## 2026-10-25 S1-fix3 · 修 `khz` 单位错 1000 倍 + 降默认波形速率

**问题 1（真 bug）：波形里出现 `khz:452542.000`**
`task_1ms()` 里 `loop_khz = s_loop_cnt / (dt/1000)` 算的是**每秒循环次数**，
却按 kHz 打印 —— 差 1000 倍。真实主循环频率 ≈ **452 kHz（2.2µs/圈）**，数值本身正常。

```c
/* 原来：Hz 当成 kHz */
s_st.loop_khz = s_loop_cnt / (dt / 1000u);
/* 现在：loops/s = cnt*1000/dt，kHz = loops/s/1000 = cnt/dt */
s_st.loop_khz = (dt != 0u) ? (uint32_t)(s_loop_cnt / dt) : 0u;
```

**问题 2（体验）：开波形后接收区被数据刷满**
本质原因：FireWater 的波形帧**就是文本行**，同一路串口只有一种解析器，
波形和接收区看的是同一批数据 —— 无法分离。

处理：
- 默认速率 **200Hz → 50Hz**（`DBG_WAVE_RATE_HZ`），每秒只 50 行，还能边看波形边读日志
- `rate 20` 更清爽；要细节时再 `rate 200`
- 文档新增 `15` 号 5.5 节"接收区被刷满怎么办"，列了 5 种做法（关自动滚动 / 降速 / 换布局 / `wave off` / 双串口）
