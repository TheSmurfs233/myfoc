## 2026-10-25 S1-fix4 · 波形"锯齿"：正弦表加线性插值

**现象**：用户反馈 VOFA+ 里波形有很多锯齿。

**分析**
测试正弦用的是 **64 点 int16 查表**。500Hz 采样、1Hz 正弦时，每个表值要重复约
`500/(64×1) = 7.8` 帧，画出来就是**阶梯**状 —— 这是测试信号本身的量化，不是链路问题。

**改动**（`app_main.c` `task_wave()`）

```c
/* 表间线性插值，消除 64 点台阶 */
pos  = s_wave_phase01 * 64.0f;
i0   = (uint16_t)pos;
frac = pos - (float)i0;
v0   = tab[i0];
v1   = tab[(i0 + 1) & 63];      /* 表是循环的 */
ch4  = v0 + (v1 - v0) * frac;
```

内存不变（还是 64×2B），每帧多 3 次浮点乘加（500Hz 下可忽略）。

**顺带整理"锯齿"的四种可能**（写进 15 号文档 5.2）：
1. 正弦阶梯 → 已修
2. `ch5` 主循环频率每 1s 才更新 → 正常，不想看就隐藏该通道
3. VOFA+ 的 `Δt` 设错（默认 1ms，实际 2ms@500Hz）→ 改成 2ms 或用 Auto
4. 丢帧造成的缺口 → 看 `stat` 里的 `drop`，涨了就 `rate` 降档

**验证**：主机 156/0 PASS；Keil 0E/0W，`Code=23350 RO=734 RW=68 ZI=8844`

## 2026-10-25 S1-tune · 波形速率默认 100Hz、上限放宽到 500Hz

**背景**
FireWater 改成纯 CSV 后帧长从 ~70B 降到 **44B**，300Hz 只占 1Mbaud 的 13%，速率限制可以放宽。

**新的带宽账**

| 速率 | 带宽 | 占 1Mbaud |
|---|---|---|
| 100 Hz（默认） | 4.4 kB/s | 4% |
| 300 Hz | 13.2 kB/s | 13% |
| **500 Hz（上限）** | 22.0 kB/s | **22%** |
| 1000 Hz | 44.0 kB/s | 44%（不做） |

**为什么停在 500Hz 而不是 1000Hz**
1. 44% 总线占用，单环缓冲没有余量吸收抖动，容易丢帧
2. `HAL_GetTick` 只有 1ms 分辨率，1000Hz 要求 `task_wave` 每毫秒必中，一次打嗝就掉帧
3. 500Hz 对 20kHz 电流环已有 **40 点/周期**，S6 观察阶跃够用

**改动**
- `board_cfg.h`：`DBG_WAVE_RATE_HZ` 50→**100**，`DBG_WAVE_RATE_MAX` 300→**500**（附带宽换算注释）
- `app_cmd.c`：help 文案 `1..300` → `1..500`
- `test_main.c`：帧率用例改成跟随 `DBG_WAVE_RATE_MAX` 自动换算（不再写死 333）

**验证（双绿）**
- 主机测试 156/0 PASS
- Keil 0 Error / 0 Warning，`Code=23306 RO=734 RW=68 ZI=8844`

## 2026-10-25 S1-proto2 · FireWater 改为官方纯 CSV + `[log]` 前缀

**背景**
用户找到 VOFA+ 帮助页的 FireWater 官方定义：

```
"<any>:ch0,ch1,ch2,...,chN\n"     或     "ch0,ch1,ch2,...,chN\n"
```

即**冒号只能有一个、且在行首**（可选标签），**不是每个通道都带名字**。
我之前写成 `t:169.347,st:1.000,...` 是错的：第二个冒号让解析失败，
VOFA+ 退回当文本显示 → 波形帧全跑到数据区刷屏（用户报的"数据区被顶上去"就是这个）。

参考工程 `workspace/myfoc/Bsp/bsp_debug.c` 也印证了：它的 `vofa_send_floats`
输出的是纯 CSV `1.23,4.56\n`，并且给日志加 `[log] ` 前缀。

**做了什么**

| 文件 | 改动 |
|---|---|
| `User/Mid/mid_vofa.c/.h` | 波形帧改为**纯 CSV**：`169.347,1.000,0.000,2.000,-773.000,452.542\n`；去掉通道名数组；加 NaN/越界钳位 |
| `User/Mid/mid_log.c` | 每条非空日志前加 **`[log] `** 标记（6 字节）；空格式串仍只发 CRLF |
| `User/Bsp/bsp_uart.c/.h` | 新增 `bsp_uart_tx_space()` |
| `mid_vofa.c` / `mid_log.c` | 写入前先查剩余空间，**空间不够就整行丢弃**（避免半行截断污染 CSV 流） |
| `test/host/test_main.c` | 波形断言改纯 CSV；日志断言加 `[log] ` 前缀 |

**效果**
- 波形行是合法 CSV → VOFA+ 消费进图，**不再进文本区**
- 日志行有 `[log] ` 且无冒号 → VOFA+ 只能当文本显示
- 接收区从此**只剩日志**，波形只在波形面板 —— "既要波形又要文本"达成
- 帧长从 ~70B 降到 **44B**（少了通道名），300Hz 只占 13% 带宽

**三条铁律（写进 15 号文档 5.1）**
1. 冒号只能出现一次且在行首
2. 每帧必须以 `\n` 结尾（VOFA+ 遇换行才提交）
3. 日志必须带 `[log] ` 且不含冒号

**验证（双绿）**
- 主机测试：**checks: 156, failed: 0, PASS**
- Keil：**0 Error / 0 Warning**，`Code=23306 RO=734 RW=68 ZI=8844`
- 冒号自检为空、源码纯 ASCII

## 2026-10-25 S1-fix3 · 修 `khz` 单位错 1000 倍 + 降默认波形速率

**问题 1（真 bug）：波形里出现 `khz:452542.000`**
`task_1ms()` 里 `loop_khz = s_loop_cnt / (dt/1000)` 算的是**每秒循环次数**，
却按 kHz 打印 —— 差 1000 倍。真实主循环频率 ≈ **452 kHz（2.2µs/圈）**，数值本身正常。

```c
/* 原来：Hz 当成 kHz */
s_st.loop_khz = s_loop_cnt / (dt / 1000u);
/* 现在：loops/s = cnt*1000/dt，kHz = loops/s/1000 = cnt/dt */
s_st.loop_khz = (dt != 0u) ? (uint32_t)(s_loop_cnt / dt) : 0u;
```

**问题 2（体验）：开波形后接收区被数据刷满**
本质原因：FireWater 的波形帧**就是文本行**，同一路串口只有一种解析器，
波形和接收区看的是同一批数据 —— 无法分离。

处理：
- 默认速率 **200Hz → 50Hz**（`DBG_WAVE_RATE_HZ`），每秒只 50 行，还能边看波形边读日志
- `rate 20` 更清爽；要细节时再 `rate 200`
- 文档新增 `15` 号 5.5 节"接收区被刷满怎么办"，列了 5 种做法（关自动滚动 / 降速 / 换布局 / `wave off` / 双串口）

**验证（双绿）**
- 主机测试 155/0 PASS
- Keil 0 Error / 0 Warning，`Code=23166 RO=862 RW=68 ZI=8844`

## 2026-10-25 S1-fix2 · 定位"串口截断"，回退 FireWater 改动

**背景**
用户编译 S1 代码，`app_cmd.c` 报 **7 个 `#8: missing closing quote`**。

**根因（编码，不是语法）**
Keil **ARMCC V5.06** 按 **GBK** 解析源码。UTF-8 中文的末字节（如 `A9 AE AF`）
正好是 GBK 前导字节，会把紧跟的 `"` 吞成双字节字符，导致字符串"少了右引号"。
- 中文**注释**：多数情况能过（首字节后接空格/ASCII，不会吞掉 `*/`）
- 中文**字符串字面量**：必崩

**做了什么**
1. 全部 `User/` 源码（15 个文件）重写为**纯 ASCII**：注释改英文、串口输出改英文。
   中文说明保留在 `docs/`。
2. 顺手修掉 **2 处浮点截断 bug**（实测会打出错误数字）：
   - `0.00005f * 1e6` = 49.99999 → 打印 `Ts=49`。新增整数宏 `FOC_TS_US (1000000/FOC_FREQ_HZ)`。
   - `CUR_A_PER_LSB*1e6` = 644.53 → 打印 `644`（文档是 645）。
     `VBUS_V_PER_LSB*1e6` = 5639.6 → `5639`（文档 5640）。
     全部加 `+0.5f` 四舍五入。
3. **建立命令行编译闭环**：本机 Keil 在 `D:\installfile\Keil_v5`，可用
   `UV4.exe -b <uvprojx> -j0 -o build.log` 全量编译，返回码 0/1/2 = OK/警告/错误。
   已写入 `docs/README.md`，以后每次改代码先编译。
4. **加固 RX DMA 切换**：查 HAL 源码确认 `DMA_SetConfig()`（每次启动都调用）只写
   `CNDTR/CPAR/CMAR`，**不写 CCR**，即 CIRCULAR 只能靠 `HAL_DMA_Init()` 编程。
   保留 `HAL_DMA_Init` 并额外 `SET_BIT(CCR, DMA_CCR_CIRC)` 双保险。

**验证**
- 命令行编译：**0 Error / 0 Warning**，退出码 0
- `Code=22886 RO-data=738 RW-data=68 ZI-data=8844` → RAM 占用 8.9KB / 32KB
- 产物 `MDK-ARM/myfoc/myfoc.axf` + `.hex` 已生成
- 回调无重复定义（`HAL_UARTEx_RxEventCallback` / `HAL_UART_TxCpltCallback` /
  `HAL_UART_ErrorCallback` 只在 `bsp_uart.c`）
- `main.c` 已接 `app_init()` / `app_loop()`

## 2026-10-25 S1 · 硬件参数闭环 + KEY/LED + 串口调试框架

**背景**
用户提供了数据手册（EG3033 / AO4606 / MT6701 / 原理图），并要求在核对无误后
实现「按键控制 LED」和「串口 debug（VOFA+ 波形 + 非阻塞发送 + 命令中断接收）」。
同时用户已自行把 NVIC 改成 ADC=0 / DMA=2 / UART=3。

**做了什么**

1. **核对 NVIC**：读 `.ioc` 与生成代码（`adc.c:158`、`dma.c:48/51`、`usart.c:147`），
   确认 ADC=0、DMA1_CH1/2=2、USART1=3、SysTick=15，与要求完全一致，无残留。✅
2. **逐条核对原理图与 `.ioc`**，得出完整引脚映射（见新文档 `19_硬件资源与引脚映射.md`）。
   确认 `CHx→HINx`（P-MOS 上管）、`CHxN→LINx`（N-MOS 下管），极性与 EG3033 真值表天然匹配，
   **不需要取反**。
3. **死区重算**：EG3033 内部 DT=60ns 且带互锁；AO4606 的 P 管关断(~80ns)快于
   N 管开通到 Vgs(th)(~157ns)，自然死区 ≈96ns。用户要求设小 → **DTG=4（23.5ns 标称）**，
   **实际生效仍为 60ns**（被驱动内部 DT 吃掉），这是正确且安全的选择。
4. **电流采样闭环**：INA240 `REF1=AGND / REF2=A3V3 → VREF=1.65V`（双向，零码值 2048）；
   Rshunt 实焊 **25mΩ**（原理图标 10mΩ）→ 0.645mA/LSB、量程 **±1.32A**。
5. **MT6701 协议闭环**：SSI 24bit（14b 角度 + 4b 状态 + 6b CRC，poly X⁶+X+1），
   DO 上升沿变化 / 下降沿采样 → **SPI Mode 1，当前配置正确不用改**；
   TCLK≥64ns → SCK 上限 15.6MHz，当前 10.625MHz 安全。
6. **建立代码骨架** `User/{Cfg,Bsp,Mid,Alg,App}`（7 个 .c），Keil 工程加 `User` 分组
   与 include 路径（直接改 `.uvprojx` XML，已校验 XML 合法）。
7. **实现 KEY→LED**：`bsp_gpio`（PF1 低有效、PA0 20ms 消抖 + 边沿事件、主循环轮询，不用 EXTI）。
8. **实现串口调试**：`bsp_uart`（RX DMA 运行时切 CIRCULAR + IDLE；TX 4KB ringbuf + 64B DMA 链式）、
   `mid_log`（手写格式化，不依赖 stdio）、`mid_vofa`（JustFloat）、`app_cmd`（ASCII 文本命令）、
   `app_main`（状态机骨架 + 任务调度）。
9. **文档更新**：新增 `19_硬件资源与引脚映射.md`、`20_框架_按键与LED.md`；
   重写 `15_框架_串口调试.md`（协议从二进制帧改为 JustFloat + 文本命令，附对比理由）；
   重写 `12` 死区章节、`13` 换算章节、`14` SSI 章节；更新 `01/18/00/README`。

**结论（关键决策）**

| 决策 | 选择 | 理由 |
|---|---|---|
| 调试串口 | **USART1（CN3 排针）** | 用户选外接 USB-TTL，零 CubeMX 改动 |
| 上行协议 | **VOFA+ JustFloat** | 6 通道 28B/帧，1kHz 占带宽 28%，无需协商 |
| 下行协议 | **ASCII 文本命令** | 串口助手直接敲，出错可见，解析放主循环零阻塞 |
| TX 实现 | ringbuf + DMA 分块，**pump 在主循环** | 不在 DMA 中断里重启，避免状态竞争 |
| RX DMA | **运行时改 CIRCULAR**（不动 .ioc） | 避免 CubeMX 重新生成丢配置，且不丢字节 |
| 按键 | **主循环轮询 + 20ms 消抖**，不用 EXTI | 唯一输入，省一个中断源，不与电流环抢 |
| 波形速率上限 | **1000Hz** | HAL_GetTick 只有 1ms 分辨率；带宽 28% 已足够 |

- **未编译**（本机没有 Keil/arm-gcc），**待用户编译验证**。
- 台架验证清单见 `01_项目进度.md` 第二节。
