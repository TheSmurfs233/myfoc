## 2026-10-25 S6-prep · 编码器改 SPI RX DMA，实测与踩坑（#66~#74）

**目标**：S6 的 Park 变换需要角度在控制链之前就绪，阻塞读（6.2us）会把 8.7us 的余量吃光。

**做法**：ADC JEOC 中断里发起 SSI 传输（CSN 拉低 + 装 DMA + 写 3 个哑字节，
约 0.9us），2.26us 的移位交给硬件，主循环取帧时数据已就绪，只做解码。

**配置归属**：DMA 请求/模式/优先级由 CubeMX 生成（hdma_spi1_rx，DMA1_Channel3，
DMAMUX 10，Normal，8bit，MINC，VERY_HIGH）；sp_ssi_init() 只补 CPAR/CMAR 并开 SPE。

**实测（20 kHz RUN，20 万帧）**
- enc CPU 时间 6152 -> **3017 ns**（min 1652），isr 1476 -> 2388 ns，isr_period 不变
- crc / ovr / late 全 **0**
- 主循环 loop 5476 -> 5958 ns

**踩到两个 bug（都很典型）**
1. log_printf 的格式串加了 %u 但漏传参数 -> 参数整体错位一格 -> %s 拿到野指针 ->
   strlen 扫内存 -> **主循环挂死 -> V/f 冻结 -> 转子被静止矢量吸住（表现为电机卡死）**。
   修复：补齐参数 + 给 log_printf 加 __attribute__((format(printf,1,2))) +
   %s 长度上限 128。
2. 只改头文件时用 -b 增量编译，pp_cmd.o 未重编 -> 新旧结构体混用 -> 输出乱码。
   教训：**改结构体必须 -r 全量重建**。

**已知问题（记录，暂不修）**：wave on 时 CRC 错误率 <7e-7 -> 3e-5，
但 ovr=0、late=0 => 字节没丢，是线路层偶发位错误（EMI / MISO 采样裕量）。
坏帧已丢弃并沿用上一帧角度，对控制无影响。

## 2026-10-25 S5-align2 · 零位标定迭代到可用精度（#55 ~ #63）

**目标**：找到转子 d 轴与 A 相轴的对应关系（电角度零点）。

**试过的 4 种方法**（全部真机验证）

| # | 方法 | 结果 | 原因 |
|---|---|---|---|
| 1 | 固定 d 轴矢量 0.5A | 转子只动 0.83° | `T ∝ sin(Δθ)`，接近平衡点时力矩不足 |
| 2 | 固定矢量渐变到 1.0A | 只动 0.27° | 加力矩无效 |
| 3 | 旋转 + 急停 / 减速 | 落点散布 ±9.4° 机械 | 停下时带滞后角，静态力矩拉不动 |
| 4 | **双向扫掠平均** | **±1.9° 机械（±13.5° 电）** | 可用 |

**方法 4 的原理**：不追求"吸住转子"，而是**测量平均跟踪误差**——
正转 7 个电周期、反转 7 个电周期，每帧累加 `err = 编码器电角度 − 磁场电角度`。
摩擦滞后在两个方向符号相反自动抵消，偏心与齿槽波动被整圈平均掉，
剩下的平均值就是零点偏差，最后 `zero += err_mean / 7`。

**踩到的关键坑**：扫掠圈数必须是**整数机械圈**。
最初用 4 个电周期（= 0.57 机械圈），散布 ±40° 电角度；
改成 **7 个电周期 = 整整 1 机械圈**后降到 ±13.5°。
原因：编码器偏心误差的周期是 1 个机械圈，非整数圈平均不掉。

**再进一步**：扫掠加长到 **14 电周期 = 2 机械圈**后，
5 次取余散布从 3.87° 机械降到 **1.52° 机械 = 10.6° 电角度（±5.3°）**，
对应 FOC 转矩损失 0.4%，**定稿**。代价是对齐时间 7.2s → 14.2s。

**验证**：主机 408/0 PASS（含"扫掠能测出 49.04° 偏移并修正 7.006°"的仿真用例）；
Keil 0E/0W，`Code=38298 RO=2046 RW=236 ZI=9252`。

## 2026-10-25 S5-align · 强制对齐求电角度零点（#55）

**背景**：`enc zero` 只是"把当前位置记成 0"的相对零点，和转子磁极、A 相轴无关；
FOC 的 Park 变换要求 `elec = 0` 时转子 d 轴正好在 A 相轴上。
`docs/10` §5 的状态机里本来就有 **ALIGN**，这次把它实现了（S5 的最后一块）。

**实现**

```
mode 1 → start → align
  1. 输出 θ_force = 0 的固定矢量，m = 0.20 → 线电压约 1.5V，电流约 0.33A
  2. 每帧（20kHz，task_adc 里）比较编码器角度，< 0.5° 持续 200ms 视为稳定
  3. mid_enc_zero() 写入 Flash（0x0801F000）
  4. 自动封波 → IDLE，打印 "OK align done, zero xx.xx deg"
```

| 保护 | 门限 | 动作 |
|---|---|---|
| 过流 | 相电流 > 0.8 A | 封波 + FAULT |
| 超时 | 1.5 s 未稳定 | 封波 + IDLE，不写零位 |
| 无编码器 | 300 ms 无有效帧 | 封波 + IDLE |

**实现要点**

- 固定矢量只在 `app_align_start()` 里写一次 CCR：矢量不变，没必要每帧重写
  （否则它会落在控制链之后，挤占余量）；
- `task_align()` 只做监视，挂在 `task_adc()` 末尾，因此天然是 20kHz；
- `app_stop()` 会中止对齐；`app_set_mode()` 在 ALIGN 期间同样被拒绝；
- 新增状态 `APP_ST_ALIGN`，`stat` 会显示 `state = ALIGN`。

**验证**：主机新增 3 组用例（未启动时拒绝 / 稳定后写零位 / 持续转动则超时），
共 **407/0 PASS**；Keil **0E/0W**，`Code=37650 RO=2046 RW=224 ZI=9216`。

## 2026-10-25 S5-time · 时序复核 + S6 裕度核算 + 优化路线记录

**当前时序（#54，RUN 20kHz，`phase` 与 `prof` 实测）**

0 ─── 28.3 ── 31.1 ── 38.6 ── 41.3 ── 47.5 ──────── 50 µs
谷底    中断    取帧   comp    写CCR   enc 完      谷底 UEV

| 环节 | 实测 |
|---|---|
| `isr`（ISR 本体） | 1.48 µs（`prof off` 后约 0.6 µs） |
| `pick` | 2.8 µs |
| `comp` | 7.5 µs |
| `wr` | 2.7 µs |
| `enc` | 6.2 µs（min 5.1 / max 18.4，max 出现在主循环被打印卡住时） |

**S6 裕度核算（关键结论）**

| 方案 | 合计 | 余量 |
|---|---|---|
| 沿用阻塞读 | 28.3+2.8+6.2+10+2.7 = **50.0 µs** | **0** ❌ |
| **SPI DMA** | 43.8 µs | **6.2 µs** ✅ |
| **控制环进 ISR** | 41.0 µs | **9.0 µs** ✅ |
| DMA + ISR | 41.0 µs | 9.0 µs ✅ 最稳 |

| # | 手段 | 收益 | 阶段 |

| 2 | TIM1 CC 触发 DMA | 同上 + 抖动归零 | S6 可选 |
| 3 | 解码再挤（取模改乘法、速度块降频） | −0.6 µs | 随时 |
| 4 | 提高 SCK | 不可行（/8=21.25MHz 超过 15.6MHz 上限） | — |

## 2026-10-25 S5-perf · 编码器耗时从 12.6µs 降到 6.2µs（#51 ~ #54）

**动机**：加 `PROF_ENC` 槽位实测后发现，单帧编码器耗时 **12652 ns**，
是预估（3µs）的 4 倍，20kHz 下占 25% CPU。

**定位手段**：新增 `enc bench` 命令（只跑 200 次 `bsp_ssi_read()`，不含解码），
并打印 `SPI1->CR1` / `RCC->CCIPR2` 原始值。

| 步骤 | 发现 | 修复 |
|---|---|---|
| 1 | `CR1=0x35D` 解码：BR=011 → /16，模式/时序全对 | SPI 配置没问题 |
| 2 | `enc bench` 7935 ns，理论 2260 ns | **HAL 阻塞收发开销 5.7µs** → 改直接读写寄存器（#53） |
| 3 | 仍 3835 ns | 轮询空转是阻塞读的固有代价（S6 用 DMA 解决） |
| 4 | 解码 3959 ns，最大项是 **CRC-6 的 18 次位循环** | 改 3 次查表（#54），省 1.34µs |

**结果**：12652 → **6152 ns**（−51%），20kHz 下 CPU 从 25% 降到 12.3%。
主机断言 **394/0**（新增"15 个真实帧 CRC 全对"，独立于自己的 CRC 实现）。

**遗留**：SPI 的 3.5µs 需要 DMA 才能消除，已列入 S6（电流环把编码器挪到 Park 之前时必须做）。

## 2026-10-25 S4-fix · `vf 0` 改为等价于 `vf off`（#50）

**现象**（用户发现）：`vf 0` 后转子不转，但**仍有电流和保持力矩**。

**原因**：V/f 曲线的低速 IR 补偿是**恒压**的：

```
v_ll = VF_BOOST_V + K*f = 1.5V   (f = 0)
m    = 1.633 * 1.5 / 12 = 0.204
```

`vf 0` 时角度冻结 → SVPWM 输出**静止电压矢量** → 相间 1.5V / 4.6Ω ≈ **0.33A 直流**，
转子被吸住并持续发热。机制上没错，但语义上不该：`vf 0` 应该是"停"。

**改动**
- `app_cmd`：`vf 0` 直接调用 `app_vf_off()`，回复 `OK vf 0 = off, duty 0.50`；
- `app_vf_set()`：`hz <= 0` 时转调 `app_vf_off()`（防御性，任何路径都一样）；
- 主机新增 1 组用例（`vf 0` 后 `on=0`）。

**为什么不改 V/f 曲线**：需要"直流持有/转子对齐"时由 **ALIGN 状态**显式给 Ud，
语义分开更清楚；V/f 曲线本身保持"转起来才需要 boost"的既有形状。

**验证**：Keil **0E/0W**，`Code=38202 RO=1906 RW=200 ZI=9232`；主机 **393/0 PASS**。

## 2026-10-25 S5 · MT6701 编码器接入（#45 ~ #48）

**结构**：`Alg(alg_svpwm) → Mid(mid_enc) → Bsp(bsp_ssi) → HAL(SPI1)`。
CubeMX 里的 SPI1（Master / 8bit / CPOL=LOW / CPHA=2EDGE / NSS soft /
PCLK2-16 = 10.625MHz）与手册要求完全一致，**没有改任何外设配置**。

**协议**（手册 §7.8.2，已实测验证）

```
bits 23..10  D[13:0]  角度，angle = D / 16384 x 360
bits  9..6   Mg[3:0]  磁场状态
bits  5..0   CRC[5:0] x^6+x+1，覆盖 18 位，MSB 先入
```

13 个原始帧逐个解码复核，**CRC 全对**；3 万帧内 **0 CRC 错误、0 IO 错误**。
说明"CSN 拉低后需 100ns 再发时钟"这条时序余量实际不需要额外延时。

**踩到的两个坑**

| # | 现象 | 根因 | 修复 |
|---|---|---|---|
| 1 | `enc` 一直 `no frame yet (frames=0)` | ADC 的触发被 MOE 门控，停机时没有 ADC 帧，`task_adc()` 不跑 | 新增 `task_enc_slow()`：停机时 1kHz 轮询，RUN 时仍走 20kHz |
| 2 | 帧数每秒只涨 1~2 | 首次修复把轮询放进了 `task_1ms()` 的"每秒"分支 | 独立 1ms 任务，实测 1000 帧/秒 |

**速度估计（新增 `spd`）**

固定 10ms 时间窗累加角度差 ÷ 时间，而不是逐帧差分（14 bit 量化在低速时噪声大）。
调试中发现并修掉一个真实缺陷：**`dt == 0` 时角度仍会累加**，
会把"没有时间跨度的角度差"算进速度；现在保留参考点，下次一起算。
另外 `dt > 2ms`（循环卡顿）与角度跳变（`enc zero`/`enc dir`）都会重置窗口。

**验证**

- 角度换算：`elec = mech x 7 mod 360` 逐点核对一致；
- 手转一圈角度单调平滑；
- 主机新增 8 组用例（解码/CRC/Mg/零位/方向/Flash 持久化/IO 错误/速度），共 **390/0 PASS**；
- Keil **0E/0W**，`Code=38138 RO=1906 RW=200 ZI=9232`。

**遗留**：`Mg` 在 0x0/0x8 间跳（怀疑位序与手册相反，待抬高磁铁确认）；
`vf 5` 的 `spd ≈ 5.00 Hz` 交叉验证待做；S6 需要把编码器改成 DMA 读取。

## 2026-10-25 S4-cordic · CORDIC 后端实验（未通过，已封存）

**动机**：查表固定占 1KB Flash，且精度 7.5e-5；G4 自带 CORDIC，可算 sin/cos
（将来无感 FOC 还要 atan2/sqrt）。做成 `TRIG_MODE` 宏可切，默认仍走 LUT。

**结构**：`Alg(alg_svpwm) → Mid(mid_trig) → Bsp(bsp_cordic)`；表搬进 `mid_trig`，
`alg_svpwm` 只调一次 `mid_trig_cos_sin()`，再用旋转恒等式推另外两相。

**踩到的坑（按发生顺序）**

| # | 现象 | 根因 |
|---|---|---|
| 1 | 自检失败、`|c|²+|s|² = 0.25` | `PRECISION` 只有 4 位，写 `23<<4` **溢出到 SCALE 位**（bit 8）→ 结果被 ×0.5 |
| 2 | 每次读到**上一次**的结果 | G4 的 CSR **没有 NRDY 位**；`RRDY=0` 才是"无待处理结果"，写 WDATA 前没排空队列 |
| 3 | 修正后：`cordic` 命令（间隔大）**数值全对** | Q1.31 / π=2³¹ 的约定正确，残差 7.2e-7 |
| 4 | **`trig` 紧循环返回 0**（1000 次连调） | 握手在连续调用下仍不可靠 |
| 5 | **V/f 20kHz 下电机两次跳闸**（1314 / 1319 mA） | 占空比被错误结果带偏，电流冲击 |

**收益评估**：`trig` 128 周期 vs LUT 142 周期，只快 10%（comp 差 0.3µs / 50µs = 0.6%）。
**结论：收益太小，风险太大 → 默认保持 LUT（#44），CORDIC 代码留在宏后面封存。**

**若将来要救活（S6/S8 需要 atan2/sqrt 时）**：
1. 改用 ST 的 `LL_CORDIC_*`（或 `HAL_CORDIC_Calculate`）官方时序，别手搓 CSR；
2. 加诊断计数器：自旋超时次数、与 LUT 的逐点最大误差（区分"返回 0 / 读到旧值 / 乱码"）；
3. 查 Errata Sheet 里 CORDIC 相关条目；
4. 用示波器/GPIO 翻转确认 20kHz 下每次调用是否真的完成。

## 2026-10-25 S4-perf4 · 使能 ART + 探针跟随 prof 开关（#38 / #39）

**背景**：`comp` 7.9µs / `wr` 2.5µs 对这么点代码来说偏慢，怀疑 170MHz 下 Flash 4 等待周期
（ART 未开）是主因；同时 `phase` 探针常开，无法测"零探针"的真实耗时。

**#38：使能 ART**

新增 `User/Bsp/bsp_sys.c`，`app_init()` 最先调用：

```c
FLASH->ACR |= (FLASH_ACR_PRFTEN | FLASH_ACR_ICEN);
```

- 只开**指令侧**（预取 + I-Cache）；**DCEN 故意不开**——运行时会擦写 Flash 存校准记录，
  数据缓存要额外处理（HAL 虽已自动关/开 DCache，但先不引入复杂度）；
- 白皮书依据：`stm32g4xx_hal_flash.c:191` 里 HAL 自己会在编程/擦除前关 DCache，
  说明指令侧与代码区不会冲突。

**实测效果（#37 → #38）**

| 指标 | 无 ART | 有 ART |
|---|---|---|
| `comp` 最小 | 7.9 µs | **7.2 µs**（−9%） |
| `pick` 最大 | 52.4 µs | **17.3 µs**（−67%） |
| `wr` | 2.5 µs | 2.5 µs（外设写，ART 无关） |

结论：ART 主要改善**取指与调度延迟**，`comp` 的 7.2µs 主要来自指令执行本身
（约 2.2 周期/指令，对带分支的浮点代码属正常），**不是瓶颈**，保留即可。

**#39：`prof off` 同时关掉 phase 探针**

## 2026-10-25 S4-perf3 · phase 改成"同帧分段耗时"（#37）

**问题**：#36 的三个数 `conv 4.7 / vf 10.5 / ccr 12.8` 加起来 **12.8µs**，
可主循环周期只有 **7.7µs**（129kHz）—— 数学上不可能是同一帧。
根因是三个标记各自**独立取最小**，min 之间不可相减。

**改动**：把探针语义从"距中断的绝对时间"改成"**相邻阶段的耗时**"，
时间戳逐级传递，保证三段来自同一帧：

```
t_ref ──pick──► t_pick ──comp──► t_comp ──wr──► t_wr
```

| 标记 | 区间 |
|---|---|
| `pick` | 中断入口 → 主循环取走该帧（调度延迟） |
| `comp` | 取走 → V/f + SVPWM 算完 |
| `wr` | 算完 → CCR1~3 写完 |

**顺带确认**：查表后 `vf − conv` 从 8µs 降到 **5.8µs**，
说明删掉探针里的 64 位除法（#36）确实回收了约 2µs。

**验证**：Keil **0E/0W**，`Code=33442 RO=1866 RW=152 ZI=9152`；主机 **350/0 PASS**。

## 2026-10-25 S4-perf · phase 参考时间戳快照 + SVPWM 查表（#35）

**背景**：`phase` 的 min/max 出现 `ccr min(6µs) < vf min(12µs)` 这种不可能的组合，
而 `conv→vf` 相差 8µs，怀疑是三次 `cosf()` 的开销。

**A. 参考时间戳每帧快照**

原来每个 mark 都读全局的 `bsp_adc_isr_cyc()`；如果处理途中又进了一次 ADC 中断，
参考就被刷新，后面的 mark 会算出偏小的值（这就是 `ccr < vf` 的由来）。
现在 `task_adc()` 开头快照一次 `t_ref`，本帧所有 mark 都用它 → min/max 同帧可比。

**B. `alg_svpwm` 的 cos 换成 256 点查表 + 线性插值**

| | 之前 | 之后 |
|---|---|---|
| 三角函数 | 3 × `cosf()`（约 6~8µs） | 3 次查表 + 插值（<1µs） |
| 精度 | 精确 | 误差 **0.0075%** = **0.3 PWM count**（1 count = 2.82mV） |
| Flash | — | +1KB 表（RO-data 870→1866），`cosf/sinf` 不再链接，Code 少 624B |

**验证**
- Keil **0E/0W**，`Code=33398 RO=1866 RW=152 ZI=9152`
- 主机 **350/0**（新增"查表 vs cosf"逐点对拍：720 点最大偏差 < 1 个 PWM count）
- 预期 `phase`：`conv ≈4µs`、`vf ≈5µs`（原 12µs）、`ccr ≈6µs`（原 16µs）

## 2026-10-25 S4-fix2 · CCR 预装载落到代码 + phase 探针改成 DWT 时差（#33 / #34）

`sConfigOC.OCPreload` 这一行。

**实测结论**：这个 CubeMX 版本**不会为 PWM 通道生成 `OCPreload`**。
证据——把 `AutoReloadPreload` 改成 Disable 后，`tim.c` 立刻出现
`htim1.Init.AutoReloadPreload = TIM_AUTORELOAD_PRELOAD_DISABLE;`（说明生成机制正常、
只写非默认值），而 OC preload 无论 Enable 还是 Disable 都不写。
HAL 拿到的是结构体零值 ⇒ `OCxPE = 0` ⇒ CCR 写入**立即生效**（在脉冲中间改宽度）。

**改动**

| 文件 | 内容 |
|---|---|
| `User/Bsp/bsp_pwm.c` | `bsp_pwm_init()` 里直接置 `CCMR1.OC1PE/OC2PE`、`CCMR2.OC3PE`（CH4 不动，从不写 CCR4），并注明 CubeMX 不生成的原因 |
| `User/Bsp/bsp_prof.h/.c` | 新增 `bsp_prof_to_ns()`（把周期数换算成 ns） |
| `User/Bsp/bsp_adc.h/.c` | 新增 `bsp_adc_isr_cyc()`（中断入口的 DWT 时间戳） |
| `User/App/app_main.c/.h`、`app_cmd.c` | `phase` 探针改造：`isr` 记录 TIM1 CNT（采样点），`conv/vf/ccr` 改成**距中断入口的 µs** |
| `test/host/*` | 新增预装载断言；phase 用例改为 cnt + us；**344 → 349 断言** |

## 2026-10-25 S4-fix · 相位探针 + 移除 UART DMA 覆盖（#32）

**背景**：用户问"能不能确定每个关键点在 50µs 里落在什么位置"，并已在 CubeMX 把
UART RX DMA 改成 CIRCULAR、把 PWM 通道的 Output compare preload 勾上。

**已确认**
- `usart.c` 已生成 `DMA_CIRCULAR`（16:04）→ **删掉 `bsp_uart_init()` 里运行时改 CIRCULAR 的覆盖**，

**新增：`phase` 命令（控制链相位探针）**

`prof` 用 DWT 量"每段多久"，`phase` 用 **TIM1->CNT** 量"每点在周期里的位置"
（1 count = 11.76ns，4250 counts = 50µs，可直接和 `CCR4=4000` 的采样点比较）：

| 标记 | 采集位置 | 含义 |
|---|---|---|
| `isr` | ADC 中断入口（ISR 内锁存） | 采样时刻 |
| `conv` | 主循环换算完 | 电流可用 |
| `vf` | SVPWM 算完 | 可写 CCR |

（多一个中断）；而 TIM1->CNT **本身就是**周期内的位置，精确且零开销。

## 2026-10-25 S1-fix4 · 波形"锯齿"：正弦表加线性插值

**现象**：用户反馈 VOFA+ 里波形有很多锯齿。

**分析**
测试正弦用的是 **64 点 int16 查表**。500Hz 采样、1Hz 正弦时，每个表值要重复约
`500/(64×1) = 7.8` 帧，画出来就是**阶梯**状 —— 这是测试信号本身的量化，不是链路问题。

**改动**（`app_main.c` `task_wave()`）

```c
/* 表间线性插值，消除 64 点台阶 */
pos  = s_wave_phase01 * 64.0f;
i0   = (uint16_t)pos;
frac = pos - (float)i0;
v0   = tab[i0];
v1   = tab[(i0 + 1) & 63];      /* 表是循环的 */
ch4  = v0 + (v1 - v0) * frac;
```

内存不变（还是 64×2B），每帧多 3 次浮点乘加（500Hz 下可忽略）。

**顺带整理"锯齿"的四种可能**（写进 15 号文档 5.2）：
1. 正弦阶梯 → 已修
2. `ch5` 主循环频率每 1s 才更新 → 正常，不想看就隐藏该通道
3. VOFA+ 的 `Δt` 设错（默认 1ms，实际 2ms@500Hz）→ 改成 2ms 或用 Auto
4. 丢帧造成的缺口 → 看 `stat` 里的 `drop`，涨了就 `rate` 降档

**验证**：主机 156/0 PASS；Keil 0E/0W，`Code=23350 RO=734 RW=68 ZI=8844`

## 2026-10-25 S1-fix3 · 修 `khz` 单位错 1000 倍 + 降默认波形速率

**问题 1（真 bug）：波形里出现 `khz:452542.000`**
`task_1ms()` 里 `loop_khz = s_loop_cnt / (dt/1000)` 算的是**每秒循环次数**，
却按 kHz 打印 —— 差 1000 倍。真实主循环频率 ≈ **452 kHz（2.2µs/圈）**，数值本身正常。

```c
/* 原来：Hz 当成 kHz */
s_st.loop_khz = s_loop_cnt / (dt / 1000u);
/* 现在：loops/s = cnt*1000/dt，kHz = loops/s/1000 = cnt/dt */
s_st.loop_khz = (dt != 0u) ? (uint32_t)(s_loop_cnt / dt) : 0u;
```

本质原因：FireWater 的波形帧**就是文本行**，同一路串口只有一种解析器，
波形和接收区看的是同一批数据 —— 无法分离。

- 默认速率 **200Hz → 50Hz**（`DBG_WAVE_RATE_HZ`），每秒只 50 行，还能边看波形边读日志
- `rate 20` 更清爽；要细节时再 `rate 200`
- 文档新增 `15` 号 5.5 节"接收区被刷满怎么办"，列了 5 种做法（关自动滚动 / 降速 / 换布局 / `wave off` / 双串口）

## 2026-10-25 S1-fix · 编译错误修复 + 建立命令行编译闭环

- 中文**注释**：多数情况能过（首字节后接空格/ASCII，不会吞掉 `*/`）
- 中文**字符串字面量**：必崩

**做了什么**
1. 全部 `User/` 源码（15 个文件）重写为**纯 ASCII**：注释改英文、串口输出改英文。
   中文说明保留在 `docs/`。
2. 顺手修掉 **2 处浮点截断 bug**（实测会打出错误数字）：
   - `0.00005f * 1e6` = 49.99999 → 打印 `Ts=49`。新增整数宏 `FOC_TS_US (1000000/FOC_FREQ_HZ)`。
   - `CUR_A_PER_LSB*1e6` = 644.53 → 打印 `644`（文档是 645）。
     `VBUS_V_PER_LSB*1e6` = 5639.6 → `5639`（文档 5640）。
     全部加 `+0.5f` 四舍五入。
3. **建立命令行编译闭环**：本机 Keil 在 `D:\installfile\Keil_v5`，可用
   `UV4.exe -b <uvprojx> -j0 -o build.log` 全量编译，返回码 0/1/2 = OK/警告/错误。
   已写入 `docs/README.md`，以后每次改代码先编译。
4. **加固 RX DMA 切换**：查 HAL 源码确认 `DMA_SetConfig()`（每次启动都调用）只写
   `CNDTR/CPAR/CMAR`，**不写 CCR**，即 CIRCULAR 只能靠 `HAL_DMA_Init()` 编程。
   保留 `HAL_DMA_Init` 并额外 `SET_BIT(CCR, DMA_CCR_CIRC)` 双保险。

3. **死区重算**：EG3033 内部 DT=60ns 且带互锁；AO4606 的 P 管关断(~80ns)快于

4. **电流采样闭环**：INA240 `REF1=AGND / REF2=A3V3 → VREF=1.65V`（双向，零码值 2048）；
   Rshunt 实焊 **25mΩ**（原理图标 10mΩ）→ 0.645mA/LSB、量程 **±1.32A**。
5. **MT6701 协议闭环**：SSI 24bit（14b 角度 + 4b 状态 + 6b CRC，poly X⁶+X+1），

   TCLK≥64ns → SCK 上限 15.6MHz，当前 10.625MHz 安全。
6. **建立代码骨架** `User/{Cfg,Bsp,Mid,Alg,App}`（7 个 .c），Keil 工程加 `User` 分组

8. **实现串口调试**：`bsp_uart`（RX DMA 运行时切 CIRCULAR + IDLE；TX 4KB ringbuf + 64B DMA 链式）、
