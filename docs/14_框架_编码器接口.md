# 子框架 · 编码器接口（MT6701）

> 状态：**已实现并实测通过**（S5，固件 #48）。本文从"设计稿"更新为"实现 + 实测"。

---

## 1. 职责边界

- **管**：MT6701 SSI 读取、原始值 → 机械角 → 电角度、零位、方向、速度估算、掉电保存。
- **不管**：无感观测器（本项目为有感方案）；PWM 发波（见 `docs/12`/`docs/21`）。

## 2. 文件与接口

```
Alg(alg_svpwm) ──► Mid(mid_enc) ──► Bsp(bsp_ssi) ──► HAL(SPI1) + CSN GPIO
```

| 文件 | 职责 |
|---|---|
| `User/Bsp/bsp_ssi.c/.h` | `bsp_ssi_read(uint8_t frame[3])`：CSN 拉低 → 收 3 字节 → 拉高 |
| `User/Mid/mid_enc.c/.h` | 帧解析、CRC-6、角度换算、零位/方向、速度、Flash 持久化 |
| `User/App/app_cmd.c` | `enc` / `enc zero` / `enc dir <0\|1>` / `enc raw` |

```c
/* bsp_ssi.h */
void    bsp_ssi_init(void);
uint8_t bsp_ssi_read(uint8_t frame[3]);       /* 0 = 成功 */

/* mid_enc.h */
typedef struct {
    uint16_t raw;       /* D[13:0] 最后一帧 */
    uint8_t  mg;        /* Mg[3:0] 磁场状态，0 = 正常 */
    uint8_t  crc_ok;    /* 最后一帧 CRC 是否匹配 */
    uint8_t  valid;     /* 至少收到过一帧 */
    uint8_t  src;       /* 零位/方向来自 flash 还是默认 */
    uint8_t  dir;       /* 0 = CCW 为正，1 = 反向 */
    float    mech_deg;  /* 去零位后的机械角 0..360 */
    float    elec_deg;  /* 电角度 0..360 */
    float    spd_hz;    /* 电角频率，带符号 */
    float    spd_rpm;   /* 机械转速，带符号 */
    float    zero_deg;  /* 保存的零位 */
    uint32_t frames, crc_errs, io_errs;
} mid_enc_t;

void     mid_enc_init(void);
void     mid_enc_update(void);        /* 每帧调用一次 */
const mid_enc_t *mid_enc_info(void);
uint8_t  mid_enc_zero(void);          /* 当前位置记为电角度 0，写 Flash */
uint8_t  mid_enc_set_dir(uint8_t d);  /* 0/1，写 Flash */
uint8_t  mid_enc_crc6(uint32_t bits18);  /* 供主机测试 */
```

## 3. 硬件与 SPI

| 项 | 值 | 来源 |
|---|---|---|
| 片选 CSN | **PA15**（GPIO 推挽，初值高） | `gpio.c` / `main.h` |
| SCK / MISO / MOSI | **PB3 / PB4 / PB5**（SPI1，AF5） | `spi.c` |
| 模式 | Master，2 线，8 bit，MSB first | `MX_SPI1_Init()` |
| CPOL / CPHA | **LOW / 2EDGE → Mode 1** | 手册要求下降沿采样 |
| 波特率 | **10.625 MHz**（PCLK2/16） | 手册上限 15.6 MHz |
| NSS | 软件（`SPI_NSS_SOFT`） | CS 由代码控制 |
| 调试口 | PA13/PA14 = **SWD**（非 JTAG） | 否则 PA15/PB3/PB4 会冲突 |
| 传输耗时 | 24 bit / 10.625 MHz = **2.26 µs**（含 HAL 开销约 3 µs） | 实测 |

> **CSN 到第一个时钟的 100ns（TH）不需要额外延时**：实测 3 万帧 CRC 零错误，
> HAL 的调用开销已足够。若将来换更快的 SPI 或改寄存器直写，需要重新评估。

## 4. SSI 协议（手册 §7.8.2，已实测验证）

### 4.1 帧格式（24 bit，MSB 先出）

| 位段 | 内容 |
|---|---|
| bits 23..10 | `D[13:0]` 绝对角度（D13 = MSB） |
| bits 9..6 | `Mg[3:0]` 磁场状态 |
| bits 5..0 | `CRC[5:0]` 校验 |

```
angle_deg = D / 16384 × 360          /* 0.02197 / LSB */
```

### 4.2 CRC-6

- 多项式 **x⁶ + x + 1**（移位异或形式为 `0x03`）；
- 覆盖 **18 位**（D[13:0] + Mg[3:0]），**MSB 先入**，初值 0；
- 实现见 `mid_enc_crc6()`，主机用例覆盖。

### 4.3 磁场状态 Mg[3:0]

| 位 | 含义 |
|---|---|
| `Mg[1:0]` | 0=正常 1=磁场过强 2=磁场过弱 3=保留 |
| `Mg[2]` | 1=旋钮按下（PUSH） |
| `Mg[3]` | 1=超速（手册定义） |

> ⚠ **实测存疑**：1mm 气隙、转子静止时 `Mg` 在 `0x0` 与 `0x8` 之间跳变，
> 而角度值完全不变（CRC 均正确）。停机不可能"超速"，怀疑 **Mg 位序与手册相反**
> （0x8 → Mg[0]=1 = 磁场过强）。**待确认**：把磁铁抬到 3~4mm 再读 `enc`，
> 看是否变成"过弱"的值。角度本身不受影响。

## 5. 角度处理

```c
mech = D * (2π / 16384)                    /* 机械角 */
mech = wrap2pi(mech - zero_rad)            /* 去零位 */
elec = mech * 7                            /* 极对数 = 7（board_cfg.h） */
if (dir) elec = 2π - elec                  /* 方向翻转 */
```

- 零位与方向保存在**独立 Flash 页 `0x0801F000`**（magic `'ENC1'`，CRC16-CCITT），
  不触碰电流校准记录（`0x0801F800`）；
### 4.x 采集方式：ADC 中断里发起 + SPI RX DMA（#66~#74）

```
ADC JEOC 中断（约 28.3 us）
   └─ bsp_ssi_start()   CSN 拉低 + 装 DMA + 写 3 个哑字节（约 0.9 us）
        └─ 硬件移位 24 bit / 10.625 MHz = 2.26 us，RX DMA 自动收 3 字节
主循环取帧（约 31 us）
   └─ mid_enc_update() → bsp_ssi_poll() → 数据已就绪，只做解码
```

| 资源 | 分配 |
|---|---|
| DMA 通道 | **DMA1_Channel3**（USART1_RX/TX 用 1/2） |
| DMAMUX 请求 | **10 = SPI1_RX** |
| 模式 | Normal、8 bit、内存自增、**优先级 VERY_HIGH** |
| NVIC | CubeMX 默认会勾选 Ch3 中断；本驱动**轮询 TC 标志**，从不置 TCIE，因此**不会触发** |

**配置归属**：DMA 的请求/模式/优先级全部由 **CubeMX** 生成（`MX_DMA_Init` → `HAL_DMA_Init(&hdma_spi1_rx)`）；
`bsp_ssi_init()` 只补 `HAL_DMA_Start()` 才会做的事（CPAR/CMAR）并使能 SPE，避免两份配置打架。

**实测收益（20 kHz RUN）**

| 项 | 阻塞读（#64） | DMA（#74） |
|---|---|---|
| `enc` CPU 时间 | 6152 ns | **3017 ns**（min 1652） |
| `isr` | 1476 ns | 2388 ns（多了 3 个哑字节） |
| `late` / `ovr` / `crc` | 0 / — / 0（12 万帧） | **0 / 0 / 0**（20 万帧） |

**已知问题（记录，暂不修）**：开 `wave on` 后 CRC 错误率从 <7e-7 升到约 3e-5，
但 `ovr = 0`、`late = 0`，说明字节没丢、是**线路层偶发位错误**（EMI 或 MISO 采样裕量）。
坏帧已被丢弃并沿用上一帧角度，对控制无影响。彻底解决需要硬件（MISO/SCK 串 22~100 Ω）
或把 CSN 拉高改到 DMA 完成中断里。

**健壮性**：`bsp_ssi_start()` 连续 4 个周期仍 busy 时强制复位（`bsp_ssi_abort()`）；
TXE 自旋上限 128 次（旧值 20000 在 ISR 里最坏会阻塞 1 ms）。

### 5.1 两种“零点”，不要混淆

| 手段 | 含义 | 用途 |
|---|---|---|
| `enc zero` | 把**当前机械位置**记为电角度 0 | **相对零点**，只适合观察/复现实验 |
| **`align`** | 双向扫掠测量零点偏差并修正 | **FOC 需要的绝对零点** |

### 5.2 `align` 的最终方案：双向扫掠平均（#63）

```
mode 1 → start → align        （约 14 秒）
  1. 幅值 0.15 → 0.45（A 相约 1.17A），θ 固定在 0
  2. 正向扫掠：θ 以 2 Hz 转 14 个电周期 = 正好 2 个机械圈（7 s）
     每帧累加 err = 编码器电角度 − 磁场电角度
  3. 反向扫掠：同样 14 个电周期，方向相反
  4. err 平均 → zero += err_mean / 极对数 → 写 Flash 0x0801F000
```

### 5.3 对齐算法的四个版本（全部真机验证过）

| 版本 | 方法 | 实测 | 失败原因 |
|---|---|---|---|
| #55 | 固定矢量 m=0.20（0.5A） | 转子只动 **0.83°** | `T ∝ sin(Δθ)`：越接近平衡点力矩越小，顶不过静摩擦+齿槽 |
| #56 | 固定矢量渐变到 m=0.45（1.0A） | 只动 **0.27°** | 加力矩无效 |
| #57 | 旋转 3 电周期 + 急停 | 散布 **±9.4° 机械** | 停下时转子带滞后角 δ，静态力矩拉不动 |
| #58 | 旋转 + 线性减速到 0 | 与 #57 差 **<0.2°** | 减速无效 → 瓶颈是粘滑而非冲击 |
| #60~62 | 双向扫掠（每段 4 电周期） | 散布 **±6° 机械（±40° 电）** | **扫掠圈数不是整数机械圈**，编码器偏心没被平均掉 |
| #63 | 双向扫掠（每段 7 电周期 = 1 机械圈） | ±1.9° 机械 = ±13.5° 电 | 可用 |
| **#64** | **双向扫掠（每段 14 电周期 = 2 机械圈）** | **±0.76° 机械 = ±5.3° 电** | **已采用** |

**关键教训**：扫掠必须是**整数个机械圈**。
编码器的偏心误差周期是 1 个机械圈；用 4 个电周期（0.57 圈）平均不掉，
换成 **7 个电周期（整整 1 圈）**后误差从 ±40° 电角度降到 ±13.5°。

### 5.4 精度与后续改进

| 扫掠长度 | 取余散布（机械） | 折合电角度 | 单次耗时 |
|---|---|---|---|
| 4 电周期（0.57 机械圈） | 12.4° | ~87° | 6.2 s |
| 7 电周期（1 机械圈） | 3.87° | 27° | 7.2 s |
| **14 电周期（2 机械圈）** | **1.52°（±0.76°）** | **10.6°（±5.3°）** | **14.2 s** |
| 28 电周期（4 机械圈，未采用） | 预计 ~0.4° | ~5° | 28 s |

**当前精度**：±5.3° 电角度 → FOC 转矩损失 `cos(5.3°) ≈ 0.996`（**0.4%**），
已低于其他误差源（电流采样、死区、PWM 量化），**定稿在 14 电周期**。

**剩余噪声来源**：转子粘滑（电流只比静摩擦大一点，跟随不平稳），
表现为正/反向误差不完全对称（如 fwd −12.94 / rev −0.61 度）。

**最终手段**：S6 闭环跑起来后，可用“让 id 最小化”的方法进一步精修。

状态机定义见 `docs/10` §5。

## 6. 速度估算

**固定时间窗**（`ENC_SPD_WINDOW_MS = 10`），而不是逐帧差分：

```
窗口内累加：dm（机械角差，最短路径）、de（电角差）、dt（DWT 周期）
spd_hz  = (de / dt) / 2π          电角频率（带符号）
spd_rpm = (dm / dt) × 60 / 2π     机械转速（带符号）
```

设计要点：

| 情况 | 处理 |
|---|---|
| `dt == 0`（同一时刻连调） | **不累加、不更新参考点**，下次一起算 |
| `dt > 2ms`（循环卡顿/刚标零） | 重置窗口，避免 2π 绕回混叠 |
| 角度跳变（`enc zero` / `enc dir`） | 重置窗口 |
| 更新率 1kHz / 20kHz | 窗口按**时间**触发，与更新率无关 |

精度：14 bit（0.02197°/LSB）在 10ms 窗口下，低速也够用；
实测 70 Hz（600 rpm）输入下误差 < 1%（主机用例锁定 ±3 Hz）。

## 7. 时序与数据流

### 7.1 在 50µs 周期里的位置

```
µs   0        23.5  26  28   31        38    41        44   50
     │         │     │   │    │         │     │         │    │
   谷底      ADC触发 │ JEOC 取帧     算完 写CCR  enc读完  谷底
                       └─ 控制链 13µs ─┘  └ 3µs ┘
```

**编码器读在控制链之后**，3µs 传输不占用 `pick→comp→wr` 的实时路径。
代价是角度"晚一帧"，S5 无影响。

### 7.2 更新率

| 状态 | 触发源 | 频率 |
|---|---|---|
| RUN（桥臂开） | `task_adc()`，由 ADC JEOC 驱动 | **20 kHz** |
| 停机（IDLE 等） | `task_enc_slow()`，主循环 1ms 节拍 | **1 kHz** |

> 关键：**ADC 的触发被 MOE 门控**，桥臂关闭时没有 ADC 帧，
> 所以停机时必须单独轮询，否则 `enc` 永远不更新（S5 踩过这个坑）。

### 7.3 实测耗时（2026-10-25，DWT `prof` 的 `enc` 槽位 + `enc bench`）

| 版本 | `enc bench`（只读 SPI） | `prof enc`（整帧） | 解码部分 |
|---|---|---|---|
| 初版 HAL `HAL_SPI_Receive` | 7935 ns | 12652 ns | 4717 ns |
| 直接寄存器（#53） | 3835 ns | 7794 ns | 3959 ns |
| + 查表 CRC / 去拷贝（#54） | **3535 ns** | **6152 ns** | **2617 ns** |

构成（#54）：

```
SPI 传输 2260 ns   24 bit @10.625MHz，硬件下限
SPI 轮询 1275 ns   CPU 空转等 RXNE（阻塞式逐字节读的固有代价）
解码+速度 2617 ns  CRC 查表后从 3959 降下来
合计 6152 ns       20kHz 下占 12.3% CPU
```

- **10.625MHz 已是最快合法档位**：MT6701 要求 TCLK ≥ 64ns（≤15.6MHz），
  `/8` = 21.25MHz 超限，所以 `/16` 就是上限；
- **SPI 的 3.5µs 只能靠 DMA 消除**，属 S6 计划内（电流环需要角度在 Park 之前）；
- CRC-6 改成 3 次查表（64 项表），表已用**板上 15 个真实帧**交叉验证，
  主机测试独立覆盖（不依赖自己的 CRC 函数）。

### 7.3 `wave` 通道

`wave` 现为 **10 通道**（500Hz 上限）：
`t, dutyA/B/C, ia/ib/c, enc_mech, enc_elec, enc_spd_hz`。

| ch | 内容 |
|---|---|
| 0 | uptime (s) |
| 1~3 | 三相占空比 |
| 4~6 | ia/ib/ic (A) |
| 7 | 编码器机械角 (deg) |
| 8 | 编码器电角度 (deg) |
| 9 | **电角速度 (Hz)**，与 `vf` 指令同单位，便于直接对比 |

### 7.4 后续提速路线（记录备查）

当前 6.2µs 的瓶颈**不在算法**，而在"阻塞式 SPI"：

```
SPI 传输 2260 ns   24 bit @10.625MHz（硬件下限，MT6701 上限 15.6MHz，/8 会超）
SPI 轮询 1275 ns   CPU 空转等 RXNE
解码+速度 2617 ns  已用查表 CRC 压过一轮
```

按收益排序的后续手段：

| # | 手段 | 预计收益 | 代价 / 适用阶段 |
|---|---|---|---|
| 1 | **SPI RX DMA**：CSN 拉低后启动 `HAL_SPI_Receive_DMA`，传输期间 CPU 做别的事 | **−3.5 µs（消掉全部轮询）** | 需 DMA 通道 + 完成回调；**S6 必做**（编码器要挪到 Park 之前） |
| 2 | **硬件触发 DMA**：再进一步用 TIM1 的另一个 CC 通道触发 SPI DMA，彻底与周期同步 | 同上，且抖动为 0 | 多占一个 CC 通道 |
| 3 | 解码再挤：电角度取模改成一次乘/取整（不用 while 循环）、速度块降频到每 10 帧一次 | −0.6 µs | 改动小，随时可做 |
| 4 | 提高 SCK：**不可行**，`/8 = 21.25MHz > 15.6MHz（TCLK 64ns）` | — | — |
| 5 | 双 SPI / 多通道并联：无收益（帧本身只有 24 bit） | — | — |

**注意**：DMA 方案下"读到的角度晚一帧"依然存在（DMA 完成时角度才可用），
S6 里若需要更贴近电流采样时刻，可用 `ω·Δt` 做角度补偿（`docs/16` §7 已列）。
