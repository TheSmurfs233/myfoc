# 08 新工程落地清单

> 从零搭建时，按此清单逐项打钩。全部完成 = 流程已落地。

---

## 阶段 0：工程骨架（半天）

- [ ] 目录结构建立

```
工程根/
├── docs/               文档
├── test/
│   ├── host/           主机仿真
│   ├── accept/         串口验收脚本
│   └── doc_check.py    文档检查
├── workflow/           本流程（复制）
└── <源码目录>
```

- [ ] `docs/00_开发日志.md` 建立（写第一条"项目启动"）
- [ ] `docs/01_项目进度.md` 建立（填 A 阶段的需求/约束/阶段计划）
- [ ] `docs/10_框架_主框架.md` 建立骨架（分层、启动流程、时序）
- [ ] `docs/18_待确认清单.md` 建立（把没想清楚的问题先记下）
- [ ] `docs/90_已知问题与限制.md` 建立（先写"暂无"）
- [ ] 版本号宏建立（如 `FW_BUILD_ID`），启动时打印
- [ ] 第一条提交：`chore: 工程骨架 + 文档体系`

---

## 阶段 1：可构建（半天~1 天）

- [ ] 固件工程可编译，**0 Error 0 Warning**
- [ ] 主机仿真框架可编译运行（fake HAL + 1 条断言）
- [ ] `doc_check.py` 可运行（先只查版本号一致性）
- [ ] 三个脚本串成一个 `verify.sh`
- [ ] 提交：`build: 三方验证骨架就绪`

> 此时还没有任何功能，但**"改坏了能立刻知道"**的能力已经建立。

---

## 阶段 2：可观测（1 天）

- [ ] 串口（或其它）调试通道可用，能收发文本命令
- [ ] `help` 命令 + `30_命令手册.md` 同步
- [ ] 关键状态查询命令：`stat`（状态机）、`fault`（故障）、`ver`（版本）
- [ ] 能打印"内部量"的诊断命令（为后续调试准备）
- [ ] 提交：`feat: 调试通道与状态查询`

> **没有可观测性就没有验收**。这一步不能省。

---

## 阶段 3：第一个可验证功能（按阶段计划推进）

- [ ] 写出阶段方案（`templates/t_阶段方案.md`）
- [ ] 主机测试先行（能测的部分）
- [ ] 实现 + 版本号 +1
- [ ] 三方验证通过
- [ ] **上板实测**，数据进开发日志
- [ ] 验收脚本 `test/accept/sN_accept.py`
- [ ] 更新进度表与框架文档
- [ ] 提交：`feat: S0 <能力> (实测 …)`

之后每个阶段重复阶段 3。

---

## 每个功能开发时的自检

```markdown
开工前
- [ ] 这个功能在 docs/01 里有对应阶段吗？
- [ ] 验收标准可量化吗？
- [ ] 能仿真吗？不能的话理由写了吗？

实现中
- [ ] 算法层有没有 HAL 依赖？（有 → 拆分）
- [ ] 边界（0/饱和/NaN/超时）处理了吗？
- [ ] 关键判据用的是物理不变量吗？
- [ ] 模式切换有硬优先级吗？

提交前
- [ ] 构建 0E/0W
- [ ] 主机测试全过
- [ ] 文档检查通过
- [ ] 版本号 +1（要烧录的话）
- [ ] 文档已同步（进度/框架/参数/命令）
- [ ] 提交信息含根因与验证

上板后
- [ ] 数据记进开发日志
- [ ] 验收标准逐条核对
- [ ] 进度表更新
- [ ] 发现的新坑写进框架文档
```

## 常见"落地失败"的征兆

| 征兆 | 说明 | 补救 |
|---|---|---|
| `01_项目进度` 一周没更新 | 进度已不可信 | 立刻补，冻结当前状态 |
| 提交信息都是 "update" | 历史失去价值 | 从下一次开始写根因 |
| 主机测试从来没跑 | 回归保护缺失 | 先补 10 条最关键的断言 |
| `doc_check.py` 总失败就不管了 | 检查形同虚设 | 修到绿，或删掉该项检查 |
| 同一类 bug 反复出现 | 没做"推翻假设"记录 | 补 `07` 的症状-根因表 |
| 调试全靠 printf 临时加 | 观测性不足 | 固化成诊断命令 |

## 最小投入的落地顺序

如果时间有限，按此顺序：

```
1. 版本号 + 启动打印            （10 分钟，收益最大）
2. docs/01 进度表              （30 分钟，决定项目不迷路）
3. 一条"内部状态"诊断命令       （1 小时，决定能不能调试）
4. 版本号一致性检查脚本         （30 分钟，防文档过期）
5. 主机测试框架 + 10 条断言     （半天，防回归）
6. 其余文档                    （随阶段推进补齐）
```
